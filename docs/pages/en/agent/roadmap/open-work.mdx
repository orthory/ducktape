# Open Work

This page tracks implementation gaps that agents should not accidentally present
as finished.

## WireGuard Tunnel Runtime

`crates/system/wireguard-upgrade` remains a protocol leaf: no `bin/node` or
`bin/noded` consumer applies its validated `TunnelInstallPlan` through defguard
`WGApi`. The next slice is a mesh module that emits upgrade effects, a reactor
worker that drives `WGApi`, an `admission_root` producer that fails closed until
the finalized admission commitment exists, and a responder-side install-plan
constructor.

The two mesh contracts (`valset::mesh` and `wireguard-upgrade`) should
collapse onto one shape. A privileged Linux netns e2e that creates a real
WireGuard interface is still deliberately descoped.

## Demotion And Promotion Edges

A validator removed at epoch cutover still halts instead of staying online as a
sync/observer. Joiner promotion itself has shipped: a parked joiner can sync an
admitting boundary, write a promotion checkpoint, reboot, and vote. Do not list
that as missing.

The remaining promotion-adjacent operator work is the stale local-state story:
pre-recovery or damaged recovery directories fail loudly rather than migrating,
and demoted nodes do not yet fall back into an observer role automatically.

## Replay Nonces

The ordered frame carries `(origin, seq)`, but replicated state does not enforce
per-origin nonce monotonicity. A byte-identical cross-epoch replay is currently
gated only by the per-engine finalization dedup; committed nonce state is the
planned durable replacement.

## Restart-Recovery Compatibility

Restart recovery is live: checkpoints, op-journal replay, cutover records, and
floor certificates recover current nodes. The edge is an older/pre-recovery
storage directory: if local state exists without a recovery checkpoint, boot
fails loudly and tells the operator to wipe/re-sync rather than migrating in
place.

## Agent/Reactor Product Path

The agent module exists, and demo/tests show the model-output-as-ordered-op
pattern. `bin/node`/`bin/noded` do not run an agent LLM worker yet: the node
worker set is empty, production genesis does not include `agent`, and the path is
not wired to tasks as live operator UX.

## duckfs Client Stack

duckfs Phases 1–2 are shipped: the rebuilt `files` module (staging, atomic
per-path-CAS commits, snapshots, pins, watches, snapshot-addressed reads),
resolver-backed state sync to full possession, restart durability, and the
noded HTTP surface. Do not list those as missing. Nothing mounts it yet: the
checkout/commit engine (`duckfs-client`, the `.duckfs/` index), the CLI, the
FUSE mount, and the app FilesView rebuilt on duckfs verbs are Phases 3–5 and
remain open. The `memory` module was deleted — absorbed by duckfs (generations
became snapshots, `duck://memory/...` became `duck://files/...`). The
automations memory-watch trigger was removed with it; filesystem-change
automations would return as a new duckfs-watch trigger, a fresh feature, not a
migration.

## Module Integration Wave

The next module wave is design/spec work before implementation: automations
deliver to inbox via `Deliver`; agents can claim jobs; and tasks can be modeled
as obligations with deadline state, cure/escalation lineage, and atomic
cross-module creation.
