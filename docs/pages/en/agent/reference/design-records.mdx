## Pruning Test

Before keeping a plan under `docs/superpowers/plans`, ask four questions:

1. Does an operator still execute it?
2. Does a future implementer need unresolved decisions from it?
3. Is it referenced by code, a skill, or an ADR?
4. Is the behavior already proven by checked-in tests and summarized in Vocs?

If the answer is only the fourth item, fold the durable summary into Vocs and
delete the plan. If a code comment points at the plan, retarget it to the ADR,
spec, test, or Vocs page that now owns the fact.
