# Design Records

Use this page to decide whether to read, update, or prune a non-page doc.
Maintained reader docs belong in `docs/pages`; temporary planning notes should
not stay in the repo once code, tests, runbooks, or ADRs own the durable facts.

## Pruning Test

Before keeping a temporary plan in the repo, ask four questions:

1. Does an operator still execute it?
2. Does a future implementer need unresolved decisions from it?
3. Is it referenced by code, a skill, or an ADR?
4. Is the behavior already proven by checked-in tests and summarized in Vocs?

If the answer is only the fourth item, fold the durable summary into Vocs and
delete the plan. If a code comment points at the plan, retarget it to the ADR,
test, runbook, code owner, or Vocs page that now owns the fact.
