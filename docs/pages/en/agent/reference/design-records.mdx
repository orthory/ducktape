# Design Records

Use this page to decide whether to read, update, or prune a non-page doc.
Maintained reader docs belong in `docs/pages`; `docs/superpowers` is for
reviewed active design records, approved specs, and live execution plans that
have not yet been folded into reader docs, ADRs, runbooks, tests, or code.

Related: [human Design Records](/en/human/reference/design-records) is the
reader-facing twin, [Repository Map](/en/agent/reference/repository-map) locates
source surfaces, [Gotchas](/en/agent/reference/gotchas) lists recurring traps,
and [Open Work](/en/agent/roadmap/open-work) tracks live gaps.

## Pruning Test

Before pruning a temporary plan or spec, ask four questions:

1. Does an operator still execute it?
2. Does a future implementer need unresolved decisions from it?
3. Is it referenced by code, a skill, or an ADR?
4. Is the behavior already proven by checked-in tests and summarized in Vocs?

If the answer is only the fourth item, fold the durable summary into Vocs and
delete the plan. If a code comment points at the plan, retarget it to the ADR,
test, runbook, code owner, or Vocs page that now owns the fact.
