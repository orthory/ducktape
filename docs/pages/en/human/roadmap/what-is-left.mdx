# What Is Left

The core architecture and the live control plane are in place: network state
sync, dynamic valset orchestration with epoch cutover, and a governed private
network all run over real sockets in the node e2e suite
(`cargo test -p node-bin --test cluster_e2e`), with a human-runnable
invite/join/admit ceremony in `bin/node/examples/demo-invite.sh`. What remains
is durability edges, demotion behavior, WireGuard runtime wiring, and product
depth.

## Done (was open)

- **Network state sync.** A running validator serves the state-sync wire
  protocol (manifest, chunked snapshots, live qmdb op-range serving via
  `serve_sync`); a joiner rebuilds every module over it and composes the source
  app-hash. Snapshot serving is the finalized-boundary capture cache.
- **Dynamic valset orchestration.** The `ValsetOrchestrator` watches finalized
  valset state, schedules a deterministic cutover, respawns the engine over the
  new participant set, and rotates channels — all driven by governance-admitted
  membership.
- **Governance and vaults.** Member-gated proposals drive membership; vaults
  replicate opaque secret ciphertext with owner-gated write integrity.
- **duckfs (files as a real filesystem).** The `files` module is now a
  consensus-replicated, copy-on-write, content-addressed filesystem — every byte
  is consensus state that survives restart, with staged uploads, atomic
  per-path-CAS commits, pinned snapshots, snapshot-addressed reads,
  resolver-backed state sync to full possession, and a noded HTTP surface. The
  checkout/commit engine (`crates/duckfs/client`), `ducktape-fs`
  checkout/status/commit/pin loop, and FUSE-gated `mount` verb also exist. The
  old memory/workspace role is absorbed by duckfs snapshots and `duck://files/...`
  evidence. Remaining work is the app FilesView/UX rebuilt on duckfs verbs.

## Durability And Promotion

- ~~Restart/recovery from persisted state~~ — shipped: a write-ahead op journal
  plus periodic checkpoints of the in-memory modules recover the composed
  app-hash on boot, and the engine respawns at its persisted epoch over its
  existing journal partition behind a persisted finalization floor (no
  double-apply, no double-vote). Remaining edge: a pre-recovery storage dir
  (state without a checkpoint) fails loudly instead of migrating.
- A validator demoted at cutover currently halts; it should degrade to a
  sync-server. A synced joiner should be able to auto-promote to a live validator
  at an epoch boundary rather than requiring a manual restart.
- Per-origin replay nonces in replicated state. Cross-epoch replay of a
  byte-identical frame is currently gated only by the per-engine finalization
  dedup.

## Product Depth

- Origin-bound message authorship (signed frames make this available — the author
  is still a caller-supplied string).
- The basic agent/runs/dispatch/jobs loop is registered in the live node.
  Remaining product depth is richer app UX, packaged agents and harnesses,
  broader action vocabularies, and durable task obligations that feel native
  rather than like a debug surface.

## Mesh

- The mesh contract now lives in one crate: `valset::mesh` was deleted and
  `crates/system/wireguard` owns the tunnel-upgrade protocol, which the node's
  reachability plane drives at runtime. What is left is a privileged e2e that
  brings up a real WireGuard interface, still deliberately descoped.

## Deferred Deliberately

- Commit-phase crash safety and full two-phase commit remain deferred: the
  host-lent atomicity covers execute-phase behavior, and a commit-phase fault is
  now a fail-stop `SubmitError::Fatal` rather than silent corruption.
