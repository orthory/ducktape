## Pruning Test

temporary plan을 repo에 남기기 전에 네 가지를 확인한다.

1. operator가 아직 이 절차를 실행하는가?
2. future implementer에게 unresolved decision이 필요한가?
3. code, skill, ADR에서 참조하는가?
4. behavior가 이미 checked-in test로 증명되고 Vocs에 요약되어 있는가?

네 번째만 해당하면 durable summary를 Vocs로 옮기고 plan은 삭제한다. code comment가
plan을 가리키면 이제 그 사실을 소유하는 ADR, test, runbook, code owner, Vocs page로
retarget한다.
