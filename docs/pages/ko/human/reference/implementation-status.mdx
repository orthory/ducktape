# Implementation Status

이 status page는 checked-in code, test, binary에 근거한다.

## Platform Spine

- `sdk`는 module contract와 deterministic system API를 정의한다.
- `host`는 registry dispatch, FIFO follow-up drain, block commit/abort를 소유한다.
- `state`는 module root를 order-independent app-hash로 합성한다.
- `node`는 host application과 transport 또는 ordered delivery를 연결한다.
- `consensus`에는 commonware Simplex-backed orderer가 있다.
- `upgrade`는 node module set에 등록되어 있다. governance가 height-gated protocol
  upgrade를 schedule/cancel하고, validator는 readiness를 self-signal하며, node는
  activation boundary에서 committed upgrade state로부터 `protocol_version`을 stamp한다.
- `reactor`는 worker result를 일반 message로 submit하여 non-deterministic worker
  boundary를 닫는다.

## Module State

- QMDB-backed module(`kv`, `pages`, `chat`)은 실제 authenticated root와
  state-sync target을 노출한다. `pages`는 nested page tree, block, comment thread를
  함께 저장하고, `chat`은 entity당 record 하나를 쓴다.
- Forge는 git state에서 32바이트 state root를 계산하고 install 전에 object closure를
  verify한다.
- Snapshot-style module(`valset`, `saga`, `tasks`, `governance`, `vaults`,
  `inbox`, `automations`, `files`, `memory`, `jobs`, example `directory`)은
  module에 맞는 canonical byte를 사용한다.
- system crate에는 WireGuard tunnel-upgrade protocol과 그 apply layer를 함께
  담은 `crates/system/wireguard`도 있다(validation은 crate root,
  effect는 `wireguard::effect`).
- chat(단일 storage-owning chat module; messaging/agent facade가 folded-in)은
  demo와 app daemon(`noded`)에 등록되어 있다.
- module wave가 업무용 surface를 채운다: inbox는 notification을 원인과 같은
  block에서 commit되는 follow-up op로 배달하고(P2), automations는
  user-authored chat post를 operator rule로 평가하며 probe-before-emit
  follow-up을 emit하고, files는 content-addressed manifest만 commit하며 chunk
  byte는 digest-and-length verification 뒤 node-local에 남고, memory는 prefix
  watch와 인용 가능한 `duck://` read를 갖춘 generation-pinned shared agent
  workspace이고, jobs는 view lease와 permissionless reclaim을 가진
  first-claim-wins work board다.

## Verification Surface

- `cargo test --workspace`는 Rust workspace를 검증한다.
- `cargo run -p demo`는 in-process multi-module walkthrough를 실행한다.
- `cargo test -p demo --test network_joiner_full`은 joiner가 state-sync wire
  protocol만으로 모든 module을 rebuild하고 source app-hash와 match함을 증명한다.
- `bin/node/examples/demo-invite.sh`는 human-runnable onboarding ceremony를 real
  socket 위에서 구동한다. founder `init`, invite, friend `join`, founder `admit`,
  refreshed invite 이후 두 node가 하나의 network로 boot하고 RPC-submitted directory
  op에 converge한다.
- `cargo test -p node-bin --test cluster_e2e`는 automated real-socket node lifecycle
  gate다. three-validator convergence, RPC-submitted message의 consensus crossing,
  cross-node governance vote, live epoch cutover, sync-only joiner의 post-cutover state
  rebuild를 검증한다.
