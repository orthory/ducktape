## Historical Material

implementation plan은 code가 ship된 뒤 product documentation으로 유지하지 않는다.
오래 살아야 하는 내용은 Vocs page, ADR, module comment, test로 옮긴다.

이번 pass는 pages/comment, agent visibility, agent setup simplification, chat
polish, huddle pop-out, video call, node-upgrade implementation plan을 prune한다.
admission-boundary fork와 restart recovery의 historical root-cause/spec note도
현재는 Vocs와 checked-in test가 소유하므로 삭제한다. 유지되는 사실은 다음 위치에
있다.

- [Product Modules](/ko/human/modules/product-modules): pages, comments, agents,
  jobs, module wave.
- [Implementation Status](/ko/human/reference/implementation-status): checked-in
  code와 test.
- [Node Upgrades](/ko/human/network/node-upgrades)와
  [agent upgrade operations](/ko/agent/network/node-upgrades): upgrade policy와
  runbook.
- 위 ADR들: implementation branch보다 오래 살아야 하는 decision.

## Housekeeping Rules

- maintained reader doc은 Vocs가 build/index할 수 있도록 `docs/pages` 아래에 둔다.
- task checklist가 아니라 decision boundary를 담는 경우에만 ADR을 유지한다.
- operator가 아직 실행하는 절차만 runbook으로 유지한다.
- code, test, Vocs summary가 implementation plan을 대체하면 plan은 삭제하거나 접는다.
