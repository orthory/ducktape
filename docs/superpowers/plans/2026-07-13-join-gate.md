# Join Gate Implementation Plan (PR4)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Joining becomes ONE synchronous invitation-gated handshake — fail the gate → no tunnel, no lobby residence, no chain state; pass → the reply IS the admission (Redeem committed), and only then does statesync run.

**Normative spec:** `docs/adr/2026-07-13-join-protocol.mdx` (Join Protocol v1). Every task cites its section; the ADR is the source of truth for wire shapes, the V1–V9 checklist, reject codes, and timeouts. This plan is the build order (ADR §8).

**Architecture:** `GateMsg` (Request/Rejected/Admitted) replaces the advisory `LobbyMsg` announce on `CHANNEL_LOBBY`. The gating member runs the full V1–V9 checklist, then submits `Redeem` and awaits its consensus fate before answering. The joiner blocks on the reply (bounded, failover), enters statesync already holding standing. Members refuse statesync/manifest to standing-less keys. A node-owned join-state machine + one `join-state` RPC replaces the app's log-marker classification.

## Global Constraints

- Branch `join-gate`, worktree `.worktree/join-gate` (forked post-#549). PR against `dev`. Commit after every task (a 0-commit worktree gets swept by worktree-clean).

- Gates per touched crate: `cargo clippy -p <crate> --tests --no-deps`; **`-p simnode` compile+test is a standing gate here** (this PR touches the lobby/redeem wire).
- NO backward compatibility (mandate): `GateMsg` replaces the announce wire in place; old joiners/members do not interop; no version negotiation. Flag day.
- Expiry authority is the member wall clock + joiner decode (`consensus_time` is block height — no in-consensus expiry). Never re-add a consensus expiry check.
- Test-lane doctrine: node/module semantics → simnode + the governance rig; the real socket join path (process exit, tunnel install, RPC) → `NetworkShapeCluster` e2e; UI → deferred manual fleet QA (note it, don't run it).

### Task 4: Statesync strictly after admission (ADR §5)

- Server (the security boundary): the statesync/manifest channel handler (`CHANNEL_SYNC`, `grep -rn "CHANNEL_SYNC\|manifest" bin/node/src/validator`) — refuse service to any peer key without committed standing (validator OR resident). Fail-closed.

**Steps:** e2e — a node holding a valid targeted invite blob but NOT yet admitted gets zero statesync bytes (assert the server refuses; assert the joiner makes no manifest request pre-Admitted). ## Notes / risks
- The settle-await seam (Task 1 step 2) is the one genuinely new mechanism — a member must observe its own submitted Redeem committing. If the relay/submit lane doesn't cleanly report per-frame fate to on_lobby's context, that's the escalation point: surface it, don't guess. Fallback shape: member submits, then polls committed redemptions for the nonce (bounded), answering Admitted when it lands — less elegant, same contract.
- Server-side statesync fail-closed (Task 4) must NOT break the restore path or validator-to-validator sync — gate ONLY the pre-standing joiner case. Test both.
- Keep each task committed; this worktree has been swept twice when left at 0 commits.
