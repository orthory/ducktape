# Plan: Join Protocol v2 — bearer-only invites, sealed doorbell gate, no lobby

Date: 2026-07-17. Branch: `feat/join-v2`. Supersedes the invite/gate half of
ADR 2026-07-13 (Join Protocol v1); a v2 ADR lands with this change.

## The five decisions (user-directed)

1. **Bearer-only invites.** The targeted form is deleted. Rationale:
   invites are minted at member level and the target key is self-generated by
   the joiner anyway — the lock never authenticated a person, only a key the
   inviter was handed seconds earlier. What the lock DID buy (blob-in-transit
   theft-proofing) is re-provided by decision 3.
2. **The invite blob always carries WireGuard information.** The WG-less
   (TCP-reachable) invite shape is deleted. Data planes are overlay-only ("no
   mesh fallback"), so a WG-less workspace is a silently degraded tier.
   Always-present: the inviter's X25519 key, intro port, mesh port. The
   underlay *endpoint* stays reachability-dependent (a fully-NAT'd inviter has
   none; it is reached by identity via the coordinator).
3. **The token never crosses cleartext.** Under bearer, the token IS the
   admission credential, and today's `IntroRequest` carries it in plaintext
   UDP. v2 seals the intro (and every reply) to the recipient's WG X25519 key:
   ephemeral X25519 ECDH + ChaCha20-Poly1305. Only the party holding the WG
   private key pinned in the envelope-signed blob can open it — an on-path
   observer on café wifi learns nothing.
4. **The gate rides the doorbell; the lobby dies.** The intro doorbell already
   runs the full checklist before installing the tunnel peer; v1 then repeats
   it over a mesh lobby channel entered under a shared zero-authority
   `lobby_identity`. v2 merges them: the sealed intro IS the gate request. The
   member verifies it, installs the tunnel peer, then runs the SAME
   settle-then-answer it runs today (submit `GovMsg::Redeem`, hold the reply
   against the frame, resolve on the drain) and sends the sealed
   `Admitted`/`Rejected`/`Pending` back over the doorbell path (direct-UDP
   reply, or the coordinated resolver datagram). `CHANNEL_LOBBY`,
   `lobby_identity`, and the joiner's 3-round mesh gate loop all delete; the
   joiner's first-contact race now resolves straight to admission, not merely
   to "tunnel installed."

   Preserved from the v1 gate (must survive the relocation): settle-then-answer
   with `GATE_SETTLE_TIMEOUT = 30s` → `Busy`; one in-flight gate per joiner key
   (a duplicate re-arms, never double-submits); the wire-stable reject codes and
   terminal bits; V6 (nonce unspent) and V7 (issuer in valset, non-terminal)
   staying at the member because they need committed state. Because the settle
   can take up to 30s over UDP, the joiner keeps re-sending the sealed intro
   across the 90s window; the member's per-joiner dedup means the extra sends
   re-arm one pending reply, and whichever retransmit arrives after the drain
   resolves carries the answer home.

5. **Always-works is a SEPARATE follow-up, not this PR.** The café incident
   (Mac joiner on `f71e6ada` — the commit right before the CLAT46 underlay fix
   #637) is the CLAT46 bug, already fixed; confirm by retrying on a current
   build before investing further. The residual gap — a genuinely UDP-dead
   network — needs a TCP/443-carried fallback (the contained form of the
   deliberately-removed relay lane). That reopens a prior decision and touches
   nat-traversal + first-contact, NOT the token/blob/wire files this PR edits,
   so it lands as its own PR after v2.

## Atomicity — items 1 and 3 are ONE cutover, not stackable commits

Dropping targeted invites (decision 1) does not merely remove the target lock — it INVERTS a
deliberate control. Today "bearer ⇒ Client-only" is enforced in depth (the mint
constructor, the blob decoder, `handle_redeem`, and BOTH doorbells), and a test
`a_bearer_resident_token_is_rejected_as_client_only` exists precisely to forbid
what decision 1 now wants. A bearer resident token is only safe once the intro
is sealed (decision 3), because otherwise the token — now the whole admission
credential — rides cleartext UDP where any on-path observer redeems it first and
the honest joiner gets `Spent`. So decisions 1 + 3 (+ the blob-shape half of 2)
MUST land in one commit / not merge independently. This is the load-bearing
sequencing constraint of the whole change.

## Resolved sub-questions (user-blessed 2026-07-17)

- **Statesync transport identity after `lobby_identity` dies → members re-track
  a resident onto the mesh the block `Redeem` COMMITS** (not at the epoch
  cutover). Closes the window where a just-admitted resident cannot dial for
  statesync under its real key; also warms tunnels earlier. Touches the drain's
  grant path (where the valset `Grant` is observed) + the mesh oracle re-track.
- **The 30s-deferred gate reply on a NAT'd (coordinated) path → answer over the
  tunnel the intro just installed**, not a held UDP rendezvous socket. By settle
  time the tunnel exists, so the sealed `Admitted`/`Rejected` rides the
  overlay-borne mesh to the joiner's real key rather than keeping a rendezvous
  socket alive for the whole settle window.

## UI (item 6) — DESIGN HANDOFF for the UI redo (not implemented here)

A separate effort is rebuilding the iced UI wholesale; this is the spec for the
join surface to fold in rather than a diff to land now.

**Intent.** The workspace create/join flow must stop consuming the whole screen.
Only the account/user keygen stays a full-screen global gate (it's genuinely
app-wide, pre-any-workspace). Everything workspace-scoped moves onto the network
rail.

**The rail (`shell/view.rs` `network_rail`, the 62px column).**
- A `+` button at the foot opens a compact create/join surface (popover or a
  small routed panel — the redo picks the shell idiom). It is NOT a full page.
- Create: name → `workspace_create`/`init`. Join: one field — paste the `🦆`
  blob → `workspace_join`/`join`. Under v2 there is **no join-code pubkey
  pre-step** (bearer invites need no OOB pubkey), so the joiner UX is literally
  "paste one string." Drop the join-code card entirely.
- Each existing workspace is a rail item that LIVE-INDICATES its join state,
  read from the node-owned `join-state` RPC (`workspace_phase`): a small badge
  per item — joining/parked → admitted → syncing → ready, plus a distinct
  terminal-failure badge (e.g. first-contact exit-3). This replaces the
  full-screen `screens/workspace.rs` join-progress takeover as the primary
  status surface; a click on a failed item can still open a detail view for the
  reject code + detail.

**Deletions the v2 protocol enables.** No join-code screen; no lobby-identity
concept anywhere in the UI; the "Approve" button stays wired to the
`invite-accept` MANUAL fallback only (bearer resident joins redeem
automatically — the rail badge just goes ready).

**Concurrency.** The rail must handle several workspaces joining at once (each
its own badge, polled independently). No global "joining" modal.

## Item 4 implementation blueprint (fully scoped; not yet built)

The lobby collapse, ready to execute. Consensus-break is acceptable (no live
network), so this is a clean hard cutover.

**Wire (`lobby.rs`).** Replace the flat `IntroAck { nonce, installed, detail }`
with a gate-outcome reply:
```rust
enum IntroReply { Installed, Refused{detail}, Admitted{height, cap}, Rejected{code, detail, terminal} }
struct IntroAck { nonce, reply: IntroReply }
```
Post-verify acks are SEALED to the joiner's WG key (the member has it from
`verify_intro`) so the cap never leaks; a pre-verify `Refused` stays cleartext.
Delete `GateMsg` (Request/Admitted/Rejected), `gate_request`,
`encode_msg`/`decode_msg` (the CHANNEL_LOBBY wire is gone); keep `RejectCode`,
`verify_reject_code`, `redeem_reject_outcome`, `verify_join_request`/`verify_intro`.

**Doorbell → main loop, and back via shared state.** Two connectors between the
reachability-plane thread and the validator run loop (member side only; the
joiner's plane passes `None`):
- `mpsc::Sender<GateForward>` where `GateForward = { issuer, nonce, token_sig,
  joiner, proof, role, expires, joiner_wg, src, path }`.
- `Arc<Mutex<HashMap<joiner_bytes, IntroReply>>>` `gate_outcomes` — the drain
  writes the resolved outcome; the doorbell reads it. This avoids the drain
  sending on a socket it doesn't own.

**`handle_intro` (member):** open → verify → expiry(V4) → role(V8) → install
tunnel → then: read `gate_outcomes[joiner]` — `Some(outcome)` ⇒ ack the sealed
outcome; `None` ⇒ send `GateForward` (the main loop dedups) and ack sealed
`Installed`. The joiner retransmits, so a later retransmit carries the resolved
outcome home (the blessed "answer rides the tunnel the intro installed").

**Validator run loop:** replace the `lobby_ingress → on_lobby` select arm
(`run.rs:509`) with `gate_forward_rx → on_gate_forward`. `on_gate_forward`
is `on_lobby`'s body minus the mesh decode/answer: V6 (nonce spent) / V7 (issuer
in valset) / V9 (already standing) + mint cap + submit `Redeem` +
`pending_gates` — but `GatePending` now stores `{ joiner, src, path, joiner_wg,
cap, deadline }` instead of a mesh `peer`.

**Drain (`drain.rs`):** resolving a `pending_gate` writes
`gate_outcomes[joiner] = Admitted{height, cap}` or `Rejected{…}` (instead of
`lobby_tx.send`). AND on the `Applied` grant, immediately re-track the resident
onto the mesh oracle (blessed #1) so its real key can dial statesync before the
epoch cutover.

**Joiner (`first_contact_join.rs` + `replica/park.rs`):** the announcer decodes
`IntroReply` (opening the sealed ack with the node's WG keypair): `Admitted` ⇒
`AttemptResult::Admitted{height,cap}`; `Rejected{terminal}` ⇒ stop; `Installed`
⇒ keep sending; window end ⇒ `Failed`. `FirstContactOutcome` gains
`Admitted`/`Rejected`. The `first_contact` task (in `replica/wiring.rs`) on
`Admitted` saves the cap + deletes the token + sets `resident_standing` (shared
with park) and wakes park; park's 3-round `CHANNEL_LOBBY` gate FSM
(`park.rs:540-671`) is DELETED — admission now comes from first contact.

**Deletions:** `lobby_identity` (`config/mod.rs`, `config/resolve.rs`,
`boot/mesh.rs` — joiners transport under their REAL key now), `CHANNEL_LOBBY`
(`constants.rs` retire/reserve, `replica/wiring.rs`, `boot/sync_only.rs`,
`validator/wiring.rs`). Statesync's real-key PoP (v1 §5.1) is unchanged and now
the ONLY mesh identity a joiner ever uses.

**Files:** `lobby.rs`, `reachability_plane.rs`, `first_contact_join.rs`,
`replica/wiring.rs`, `replica/park.rs`, `validator/run.rs`,
`validator/run/ingress.rs`, `validator/run/drain.rs`, `validator/wiring.rs`,
`boot/mesh.rs`, `boot/sync_only.rs`, `config/mod.rs`, `config/resolve.rs`,
`constants.rs`.
