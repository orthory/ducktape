# Design: Honest Error Handling for the `tauri dev` Developer Experience

> **Status:** approved design · **Date:** 2026-07-07 · **Branch:** `feat/tauri-dev-error-handling` (off `origin/dev`)
>
> **Scope:** all three phases (P0 → P2). The owner asked to be exhaustive — cover every case.
>
> **How this was produced:** a multi-agent audit enumerated **163 failure cases** across 8 surfaces of the `tauri dev` flow (7 critical, 58 high, 67 medium, 31 low), then completeness critics and a synthesis pass distilled them into the matrix and mechanisms below. Of the 163 cases, **only 2 currently produce an actionable message** — the rest are false-success (32), crash-or-hang (24), silently-dropped (27), generic (67), or log-only (11). The audit ran on `feat/video-calls`; every error-handling file cited is byte-identical on `origin/dev` except `DucktapeProvider.tsx` (minor huddle wiring — boot/heartbeat/`fail()` structure unchanged), so line anchors are accurate but should be treated as approximate for that one file.
>
> **Resolved forks** (see §5 for rationale): node-side changes start app-side-only (M3a) with the node FATAL marker (M3b) in P1 · version/wire-compat gate = hard-refuse managed, warn remote · registry atomic-write unconditionally, flock in P1 · no new toast/notification system (reuse the huddle card vocabulary).

## 1. Problem Statement

When a Ducktape node fails to start or dies during `tauri dev`, **the failure is reported as success at every layer, and the one artifact that holds the real reason — `daemon.log` — is read by nothing that the developer can see.**

The failure travels a straight line of dishonesty:

- **`ops/dev.sh`** kills the old node, fire-and-forget re-spawns, and *unconditionally* prints `✓ node back on the fresh binary` — even when the fresh node panicked, hit `EADDRINUSE`, failed to load storage under a new wire format, or was never bounced at all. It also writes the respawned node's output to `dev-node.log`, a file the app never reads.
- **Rust (`daemon.rs` / `workspaces.rs`)** spawns via `Command::spawn()` with **no post-spawn liveness check** — no `try_wait`, no port re-probe, no log tail. A node that dies milliseconds after fork still returns `Ok` + an `http_url`. The one place with an actionable message (`usable()`) is *skipped* on the `DUCKTAPE_NODE_BIN` path the dev flow actually uses.
- **The frontend** polls `/v1/status` for 40×250ms and then rejects with a generic `the node did not come up: TypeError: Failed to fetch`. It never distinguishes *not-listening* from *listening-but-500ing* from *CSP-blocked* from *wrong-version*, never reads `daemon.log`, and (for a joiner) can spin on `starting…` forever because `classify()` only recognizes 7 join-flow markers and a plain Rust panic matches none of them.

The dev's terminal is green, the app shows a **blank console, an eternal "Setting up…" button, or a cheerful join spinner telling them to go ask a member for approval** — while the node is dead and the reason (`address already in use: 127.0.0.1:8844`, `thread 'main' panicked at…`, `stage it with bun run sidecar`) sits unread on disk. There is no React error boundary (a render throw whites out the whole window), no Retry at the point of failure, no "open daemon.log" affordance, and no persistent "the node is not okay" state — every error surface is optimistic, transient, and dismissible.

This is the worst failure shape for a developer: **a silent false-success or an ambiguous hang is more costly than a loud error.** This design makes the dev loop *honest*: a node that fails to come up says why, fast, on screen, with a way to retry and a way to read the log.

## 2. Failure-Case Matrix

Grouped by layer. Near-duplicates merged. Severity is from the **developer's** seat (false-success / silent-hang ranked above loud-error).

### Layer: `dev.sh` (harness — build, watch, restart, spawn, sweep, cfg-override, trap)

| Trigger | Current behavior | Dev sees today | Proposed handling | Proposed UX |
|---|---|---|---|---|
| Rebuilt node dies post-spawn (panic / EADDRINUSE / bad config / storage-wire incompat from a lockstep change, e.g. engine-bank 8→9) | `spawn_node` is nohup+disown; `restart_node` always logs `✓ node back` (dev.sh:33-36,55-56); assumes every rebuild is a re-syncable in-place restart (dev.sh:9-11) | Green success line for a dead node; dev tests **stale** code / a dead node | Capture child pid; brief grace; `kill -0` + probe the listen/http port (or tail for a FATAL marker) before claiming success | `✓ node back on :<port>` only after a liveness probe; else `✗ rebuilt node exited — last log lines:` + tail |
| Old node ignores/slow-walks SIGTERM; 6s wait loop expires with it still alive | Loop exits on counter, no SIGKILL escalation; fresh node collides on the held port and dies (dev.sh:53-56) | `✓ node back` while the **old** stale-binary node still serves | Escalate to `kill -9`, re-wait, and confirm the port is free before spawning | `✗ old node ignored SIGTERM after 6s — sending SIGKILL`; `✗ fresh node could not bind :<port>` |
| Respawned node logs to `dev-node.log`; app reads only `daemon.log` | `spawn_node` redirects to `${cfg%/*}/dev-node.log` (dev.sh:34); `classify`/`workspace_phase` read `<dir>/daemon.log` (workspaces.rs:876) | Crash reason lands in a file nothing reads; app phase reflects the **dead prior** run (can even show `promoted:` for a dead node) | Append the respawn to the **same** `daemon.log` the app reads (or teach the app to tail both); echo the exact log path in the restart banner | App diagnostics stay authoritative; banner names the live log |
| `make dev` while any other node runs (another worktree, fleet tile, shared :8844) | Startup sweep `pkill -f 'ducktape-node --config'` (dev.sh:82) — unscoped basename; logs "stopped a stale node from a previous session" on any kill | Silently kills **other** worktrees'/fleet nodes; framed as reaping your own | Scope to this worktree's absolute `$NODE_BIN` (as `restart_node` intends); say so when nothing matched | Only this worktree's leftover is reaped; others untouched |

| `find` absent (busybox/minimal PATH) | `find bin crates … 2>/dev/null` swallows "command not found"; loop sleeps forever (dev.sh:63) | Hot-reload silently never fires; "watcher is broken" with zero diagnostic | Probe for `find` (and that `bin/`,`crates/` exist) at startup; don't blanket-suppress `find` stderr | `✗ find not on PATH — Rust hot-reload disabled` |

| >1 workspace node running | `pgrep … | head -1` restarts only the first (dev.sh:45) | `✓ node back` but only 1 of N got new code | Iterate all matching pids per `--config`; report count | `restarting 3 nodes…` + per-node result |
| `--config` path with a space | space-delimited `sed` truncates it (dev.sh:50); bogus config → dead node under `✓` | "works on my machine" false-success | Parse `/proc/<pid>/cmdline` (NUL-delimited) or a pidfile | Hot-reload works with spaces in the data path |

| `cd app` fails (partial checkout/rename) | no `|| exit`, no `-e`; runs bun in the wrong dir (dev.sh:102-103) | `script tauri not found` in the wrong directory | `cd app || { log …; exit 1; }` (and the earlier root `cd`) | `✗ app/ not found from <root>` |
| Ctrl-C; later a manual app launch (no startup sweep) | cleanup kills only WATCH_PID + rms CFG_OVERRIDE (dev.sh:95-99); node is detached, survives; dev.sh respawn doesn't update `node.pid` | Orphan node holds ports; app **adopts** the stale-binary orphan by port; app pidfile is stale for teardown | cleanup reaps this worktree's node (scoped) or records+kills spawned pids; respawn updates `node.pid` | Ctrl-C leaves no orphan, or says one survived and how it'll be reaped |
| `DUCKTAPE_DISABLE_HEARTBEAT=1` on a live-join/multi-validator flow | exported shell-wide (dev.sh:29); every spawned node (incl. a joiner-turned-validator) inherits it; no check the node honored it | Behavior silently diverges from prod; a future typo no-ops silently | Scope to genuinely-solo dev or make opt-in; have the node echo the recognized flag at boot | Clear indication heartbeats are off and for which nodes |
| Live node exits between pgrep and ps; cold/stalled initial build; concurrent cargo target-lock | empty `ps` → "could not read --config; skip"; initial build has no timeout; target-lock "Blocking…" buried (dev.sh:40-51,71-75) | Terse skip / apparent hang / "watcher hung" | Distinguish "pid vanished" (let app respawn) from parse-fail; heartbeat "still building…"; prefix watcher output distinctly | `node already exited; app will spawn fresh`; periodic "still building…"; legible "waiting on build lock" |

| Trigger | Current behavior | Dev sees today | Proposed handling | Proposed UX |
|---|---|---|---|---|

## 3. Architecture of the Fix

Seven composable mechanisms. The **first three** (M1–M3) kill the false-success/blank-screen through-line and cover the bulk of the matrix; the rest harden the edges. Each is small and independently shippable.

### M1 — Rust `spawn_verified()` helper (the honest-liveness core)
A single function `spawn_verified(cmd, log_path, listen, http) -> Result<Child, SpawnError>` that: keeps the `Child`; does a bounded grace loop (`try_wait` for immediate death **and** a port re-probe of the http surface); on death/timeout tails the last N lines of `daemon.log` and returns an `Err` carrying `{reason, log_tail}`. Retries `spawn()` a few times on `ETXTBSY`/`ENOEXEC` (hot-reload race). Runs `usable()` on the resolved binary **including the `DUCKTAPE_NODE_BIN` env path**, trimming empty-as-unset.
- **Touches:** `daemon.rs` (`daemon_spawn`, `resolve_node_bin`/`node_binary` guard, `detach`), `workspaces.rs` (`workspace_select` spawn at :846-853, adoption gate at :832 — probe the **http** surface + server-side `/v1/status` pubkey/version before adopting).
- **Covers:** every `*-no-liveness-*`, `env*-bypasses-usable`, `spawn-race-etxtbsy`, `adopt-*` split-brain/foreign/stale, `select-spawn-no-liveness-joiner-infinite` (paired with M3), `active-repointed-before-spawn-viability` (commit `active` only on success).
- **UX:** `select`/`create`/`join` fail in ~1s with `the node for "<name>" exited on start: <daemon.log line>` (e.g. `address already in use: 127.0.0.1:8844`), instead of a 10s generic timeout.

### M2 — Rust `workspace_log_tail` command (real reason to the UI)
A Tauri command returning the `daemon.log` path + last N KB for a workspace. The frontend calls it whenever a **managed** node fails to answer and folds the last `FATAL`/`panicked at`/bind line into the error; it also powers the "Open daemon.log" affordance.
- **Touches:** `workspaces.rs`/`main.rs` (new command), `node-bootstrap.ts` (`waitUntilUp` rejection path), `actions.ts` (`connectActive` catch).
- **Covers:** `waituntilup-generic-reason`, `waituntilup-hides-daemon-log-reason`, `no-open-daemon-log-affordance`.
- **UX:** `the node for "<workspace>" failed to start: <last daemon.log error>` + a "view full log" button, not `Failed to fetch`.

### M3 — Node fatal-marker contract + broadened `classify()`
Node emits a **stable machine-readable FATAL line** (naming the cause) and a **non-zero exit** on every terminal boot failure (bind, config parse, storage/wire incompat). `classify()` gains (a) a generic crash verdict driven by **process death** (pidfile pid dead + ports unheld), and (b) broad markers (`panicked at`, start-of-line `error:`). Markers are anchored to the node's log prefix to stop content spoofing; the whole log (or a sidecar phase file) is scanned so a marker can't scroll out of the 64 KB window.
- **Touches:** `bin/node/src/main.rs` (startup error paths, e.g. :3968), `workspaces.rs` `classify()`/`read_tail` (:877-926).
- **Covers:** `classify-narrow-marker-set`, `classify-plain-panic-invisible`, `classify-unanchored-substring-spoof`, `read-tail-marker-scrolled-out`, `http-bind`, and the joiner-infinite spin (a dead process now classifies `fatal`).
- **UX:** the single most common dev failure — a panic from the code you just edited — surfaces as a fatal card with the panic message, immediately.

### M4 — dev.sh honest restart + isolation
Post-restart liveness (SIGKILL escalation → confirm port free → `kill -0` + port probe → tail on death); success line only when the probe passes. Scope the sweep to this worktree's absolute `$NODE_BIN`; match the node **literally** (not as a regex). Preflight :1430/node ports **before** the destructive sweep. Point `DUCKTAPE_NODE_BIN` at a node staged **outside** `target/`. Append the respawn to the **same** `daemon.log` the app reads (or echo its path). Restart only when the artifact hash advanced. Cleanup reaps this worktree's node and updates `node.pid`.
- **Touches:** `ops/dev.sh` (`restart_node`, `spawn_node`, sweep, watch predicate, preflight, cleanup, env exports), plus the build/sidecar path-collision break — rename the sidecar (`ducktape-node-sidecar`) or stage the dev node outside `target/` so tauri's externalBin copy can never truncate the debug node cargo just built (`tauri.conf.json` externalBin, `build.rs`, `prepare-sidecar.sh`).
- **Covers:** every `dev.sh` and most `build/sidecar` rows above.
- **UX:** `✓ node back on :<port>` is trustworthy; failures print the real reason and the log path; other worktrees/fleet tiles are never touched.

### M5 — Frontend transport classification + bounded fetches
`status()` (and the shared parse path) reject with a typed `{kind: refused|httpError|badBody|timeout|csp}`; every fetch carries an `AbortController` deadline so the 10s bound is real; validate the `NodeStatus` shape and compare `version` against an app-expected wire-compat range; ws reconnect gains backoff+cap+jitter, a liveness timer, try/catch'd parse, and an **identity re-check on reconnect**. `waitUntilUp` retries only on `refused`/`timeout` and fails fast otherwise.
- **Touches:** `transport.ts` (`postJson`/`status`/parse/ws), `node-bootstrap.ts` (`waitUntilUp`, `normalizeNodeUrl`).
- **Covers:** `waituntilup-no-up-vs-erroring`, `-no-fetch-timeout`, `-status-body-unvalidated`, `version-skew`, `ws-*`, `envelope-*`, `connect-refused-vs-5xx`, `normalizeurl-path`, `csp-blocks-remote`, `blocks-swallow`, `shutdown-*`, `heartbeat-recovery-skips-identity`, `ws-blockstream-reconnects-foreign`.
- **UX:** distinct, actionable messages — `not listening yet` vs `returned 500` vs `blocked (CSP) — loopback url?` vs `version incompatible — rebuild the node`.

### M6 — Frontend connection state machine + failure/recovery surfaces
Replace the single `connected` boolean with a phase (`connecting`\|`live`\|`reconnecting`\|`down`\|`degraded`) and split **connection** errors from transient **op** errors. Boot never dead-ends: a member/joiner startup failure routes to a dedicated **"Node failed to start"** body (reason from M2 + Retry + Open daemon.log); the joiner park loop gets a never-answered timeout; the gate always appears on registry failure; a null-node boot-retry loop auto-adopts a late node; the heartbeat down edge raises an actionable persistent banner with **Restart node** at the point of failure; a saved-remote failure falls back to local. Retry is idempotent (never re-mints).
- **Touches:** `state.ts`, `DucktapeProvider.tsx` (boot/heartbeat effects), `actions.ts` (`connectActive`/`park`/`newWorkspace`/`connectRemote`/Retry), `DucktapeConsole.tsx`, `WindowFrame.tsx`, `JoinProgress.tsx`, `OnboardingGate.tsx`.
- **Covers:** all fe-boot rows and the fe-ux recovery/steady-state rows.
- **UX:** four distinct visible states instead of one red dot; a failed boot is a framed, retryable panel; a mid-session death is a loud banner with one-click Restart + Open daemon.log; a genuinely-parked joiner still gets reassuring copy.

### M7 — Frontend error boundary + one hoisted presenter (the safety net)
A top-level `ErrorBoundary` inside `WindowFrame` (keeps the titlebar) plus `window.onerror`/`unhandledrejection` handlers funneling into it. One error presenter hoisted to `WindowFrame` so it renders identically over the gate, join room, and shell — wrapping, selectable, copyable, with a Reload/Retry action and a normalize-error helper (never `[object Object]`).
- **Touches:** `main.tsx`, `WindowFrame.tsx`, `ConsoleShell.tsx` (`ErrorStrip`), `DucktapeConsole.tsx`.
- **Covers:** `no-error-boundary-*`, `errorstrip-*`, `join-error-invisible`, `no-global-unhandledrejection`, `string-err-loses-structure`, `single-error-string-clobber`.
- **UX:** a render throw becomes a "Something crashed — Reload" panel, never a blank window; the actionable string is always on screen, full and copyable.

**Registry/verb hardening (folds into M1/M4 discipline):** atomic temp+fsync+rename + a cross-process flock around load→mutate→save (fixes corrupt-registry brick, non-atomic save, concurrent instances, create-save-orphan), a wall-clock timeout on `run_verb` (fixes the UI-freezing forget/delete hang), registry-derived Safe short-circuit for solo/inactive forget, batched teardown grace, and time-bounded `public_ip`. These are the highest-severity *non-startup* cases (a `critical` brick and a `critical` UI-wide hang) and ride along cheaply.

## 4. Phased Plan

**Phase 0 — Minimal honest core (kills false-success + blank-screen).** Ship these together; they are the whole point.
1. **M1** `spawn_verified()` (immediate-death `try_wait` + http re-probe + `usable()` on the env path + log tail) in `workspace_select` and `daemon_spawn`.
2. **M2** `workspace_log_tail` + fold the real reason into `waitUntilUp` rejection.
3. **M3(a)** broaden `classify()`/fatality to process-death + `panicked at` (unblocks the eternal joiner spinner without needing the node change yet).
4. **M4(core)** dev.sh: honest post-restart liveness + tail-on-death; scope+literal the sweep; stage the dev node outside `target/`.
5. **M6(min)** one dedicated "Node failed to start" surface with Retry + Open daemon.log, reachable from both member and joiner failures (and always land on the gate on registry failure).
6. **M7(min)** the top-level ErrorBoundary (blank-white-screen is unacceptable and one file fixes it).

After Phase 0: a node that fails to start says why, fast, on screen, with Retry and the log — the through-line is dead.

**Phase 1 — Correctness & no-more-hangs.**
- Registry atomic-write + flock + corrupt-registry recovery; `run_verb` timeout; time-bounded `public_ip`; solo/inactive forget short-circuit; batched teardown.
- **M3(b)** node-side stable FATAL marker + non-zero exit.

**Phase 2 — Steady-state polish (nice-to-haves).**

## 5. Resolved Decisions

These were the open forks; resolved as follows (owner chose the full three-phase scope and these defaults):

1. **Node-side fatal contract (M3b): app-side first, marker in P1.** M3a (drive fatality from process-death + broad markers in `classify()`) needs **zero** node-source changes and already kills the eternal-spinner, so it ships in P0. The node-side stable FATAL line + non-zero exit (M3b) lands in **P1** and stays *minimal* — a log line + exit code, not a structured status stream. Rationale: `bin/node` is consensus-adjacent and on lockstep branches touching it is heavier; the app can infer fatality without it, and the marker only makes the message nicer.
2. **No new toast/notification system.** P0 uses a dedicated "Node failed to start" failure body + the ErrorBoundary; the hoisted copyable presenter and an error *queue* land in P2 — but built on the existing huddle-card vocabulary, **not** a new design-system/toast library.
3. **The liveness check ships in production Rust.** `spawn_verified` and `usable()`-on-env-path live in `workspaces.rs`/`daemon.rs` and are **not** `cfg(debug_assertions)`-gated — a node that dies on start is worth catching in a packaged build too, and it's the single highest-value fix.
4. **Version/wire-compat gate: hard-refuse managed, warn remote.** A managed (app-spawned) node whose wire version is outside the app's expected range is refused with an actionable "rebuild the node" message; a user-supplied remote node only warns (the app doesn't control its lifecycle). Costs one maintained compat constant.
5. **Registry: atomic-write now, flock in P1.** Temp+fsync+atomic-rename lands with the P0/P1 registry hardening unconditionally; the cross-process advisory `flock` (for two `make dev` sessions sharing a `$HOME`) lands in P1 alongside it.

## 6. Non-Goals / YAGNI

- **No** DERP/relay, remote-node CSP redesign, or a general remote-connection feature — only *detect and label* a CSP-blocked fetch.
- **No** on-consensus/telemetry module (explicitly deferred per MEMORY); this is dev-loop observability only.
- **No** watchdog/supervisor that auto-restarts the node on crash beyond the bounded boot-retry; the dev stays in control.
- **No** new logging framework or structured-log pipeline — a tail command and a FATAL line suffice.
- **No** rewrite of `daemon_spawn`/`ensure_solo_config`; retire or leave, don't re-engineer the dead path.
- **No** cross-platform teardown abstraction beyond syscall `kill` + `/proc` on the dev box.
- **No** design-system/toast library; reuse the huddle card's existing vocabulary.
- **No** attempt to make hot-reload storage-migration-safe — just *detect* an incompat abort and say so (a wiped `storage_dir` is the dev's call).

## 7. Testing

**Unit / Rust:**
- `spawn_verified`: table-tests for immediate-exit (bind a port first, spawn, assert `Err` + non-empty `log_tail`), slow-bind-then-ok (assert `Ok`), `ETXTBSY` retry (rewrite the binary under the spawn), `usable()` rejects 0-byte/non-exec/empty-env.
- `classify()`: fixtures for a raw `panicked at`, an EADDRINUSE line, a content line that *contains* a marker substring (must **not** flip phase), a marker beyond 64 KB, and a dead-pid + free-port input (must classify `fatal`).
- Registry: atomic write survives a simulated mid-write kill (temp file left, real file intact); corrupt file → `.bak` + empty; concurrent writers under flock don't lose entries.
- `run_verb` timeout: point at a socket that accepts but never replies; assert it returns within the deadline.
- TOML encoding: paths with `'`/`"`/`\`/spaces round-trip; `listen` non-`SocketAddr` rejected.

**Unit / frontend:**
- `status()` typed rejects (mock 500/404/empty-body/refused/abort); `waitUntilUp` retries only on refused/timeout and fails fast otherwise; `NodeStatus` shape + version-range validation; `normalizeNodeUrl` reduces to origin and rejects `ws://`.
- ErrorBoundary renders the fallback (a child that throws); `unhandledrejection` funnels; `connectActive` failure sets the dedicated failure state and clears prior error; Retry is idempotent (asserts no duplicate workspace).

**Honest end-to-end (the real bar — drive the live app via the `tauri-debug`/`qa` skill, headless):**
1. **Port conflict:** occupy the workspace's http port, then select → assert the dev sees `address already in use: <port>` within ~2s (not a 10s spinner, not `✓`), with Retry + Open daemon.log present.
2. **Bad config:** corrupt `node.toml`, select → assert the TOML/parse reason is surfaced from `daemon.log`, not a generic timeout.
3. **0-byte binary:** truncate `DUCKTAPE_NODE_BIN` (reproduce the build.rs clobber), select → assert the actionable "rebuild / re-point" message, not `Exec format error`.
4. **Panic on boot:** inject a panic in the node startup path, join → assert JoinProgress flips to a fatal card with the panic message, **not** an eternal "ask a member to approve".
5. **dev.sh honesty:** kill the node's port before a hot-reload restart → assert dev.sh prints `✗` + the log tail, never `✓ node back`.
6. **Mid-session death:** SIGKILL the running node → assert a persistent reconnecting banner with Restart node appears (not just a red dot beside a frozen height), and Restart brings it back.
7. **Render throw:** feed a malformed projection → assert the "Something crashed / Reload" panel, never a blank window.
8. **Cross-worktree isolation:** run two `make dev` sessions → assert session 2 does not kill session 1's node and drives its own MCP socket/window.

The pass criterion for every E2E case is the same and is the whole design in one line: **the developer sees an actionable message pointing at the real reason, with a way to retry and a way to read the log — never a green success line, a blank screen, or an eternal spinner.**
