# Agent QA Fleet Dashboard — Design

**Date:** 2026-07-03
**Status:** Draft (awaiting user review)
**Author:** pairing session (byeongsu-hong + Claude)

## Purpose

Give a single web dashboard, viewable from any device over Tailscale, that shows
**the real Ducktape desktop app running for each git worktree at once** — so you
can watch agents drive and QA those apps live. One worktree → one isolated,
headless app instance → one live view tile in the dashboard.

The dev box is headless (Debian 13, no display, no sudo); everything runs
userspace under Xvfb and is reached over Tailscale. This generalizes the
already-working single-instance `~/.local/opt/remote-tauri/remote-tauri.sh`
(Xvfb → tauri dev → x11vnc → noVNC) to N worktrees behind one web port.

## Scope decisions (best-judgment defaults — confirm on review)

The user pivoted from "branch-tree control console" to "just want to see how
agents are controlling & QAing, like a dashboard." Two forks were left
unanswered and resolved by best judgment:

1. **Layout — grid now, xyflow branch-tree later.** v1 is a responsive live grid
   (the core "watch them all" value). Code is structured so an `@xyflow/react`
   branch-tree view mode can be added as a second layout without reworking the
   data layer. (User originally asked for xyflow; this defers, not drops, it.)
2. **Tile content — live app view only.** Each tile is the live app; watching it
   IS watching the agent QA. An agent activity feed (clicks/assertions/logs
   beside the view) is a clean later add and is explicitly out of scope for v1.

Also fixed by scope: **view + connect only** (no start/stop from the UI — the
fleet is script-managed), **no auth beyond Tailscale**, single tailnet ingress.

## Non-goals (v1)

- Starting/stopping/rebuilding worktree instances from the UI (script-managed).
- Capturing or replaying agent actions / tauri-debug traffic.
- Editing code or interacting with git from the dashboard.
- Any exposure beyond the tailnet; no multi-user auth.

## Architecture

```
                         Mac / phone (browser, on tailnet)
                                    │  http/ws  :6080  (ONLY exposed port)
        ┌───────────────────────────┴───────────────────────────┐
        │                    ONE websockify                       │
        │  --web ops/fleet-console/dist        (static UI + fleet.json) │
        │  --token-plugin TokenFile  ?token=<wt> → 127.0.0.1:<vncPort>  │
        └───────────────────────────┬───────────────────────────┘
                                    │ localhost only
   ┌──────────────┬─────────────────┼─────────────────┬──────────────┐
   │ worktree A   │  worktree B      │   worktree C     │   …          │
   │ Xvfb :99     │  Xvfb :100       │   Xvfb :101      │              │
   │ vite :1420   │  vite :1421      │   vite :1422     │              │
   │ tauri dev    │  tauri dev       │   tauri dev      │   (per-slot  │
   │ x11vnc :5900 │  x11vnc :5901    │   x11vnc :5902   │    HOME/env) │
   └──────────────┴─────────────────┴─────────────────┴──────────────┘
```

- **Single tailnet ingress = `:6080`.** Every worktree's x11vnc binds
  `127.0.0.1` only; the browser reaches them exclusively through the token
  router. (Easy to add TLS to that one port later.)
- **No backend service.** The console is static files; it reads `fleet.json`
  (regenerated by the script) and connects live VNC via token.

## Components

### 1. `ops/fleet.sh` — fleet manager

Generalizes `remote-tauri.sh` to N worktrees. Subcommands:

| cmd | does |
|---|---|
| `up [branch…]` | bring up an instance per worktree (all worktrees, or the named branches); (re)write `fleet.json` + token dir; (re)start the one websockify |
| `down [branch…]` | tear down all, or the named instances |
| `status` | print per-worktree slot/ports/status + connect URL |
| `refresh` | re-scan worktrees + re-emit `fleet.json` (no restart) |
| `build-console` | `bun install && vite build` the console into `dist/` |

**Per-worktree slot `i`** — assigned as the lowest free slot on first sight and
**persisted** in `<state>/slots.json` (`id → slot`), so adding or removing a
worktree never churns the ports/displays of instances already running. Freed
slots are reused.
- `DISPLAY=:99+i`, `vite=1420+i`, `x11vnc=5900+i`, `mcpSocket=/tmp/tauri-mcp-<id>.sock`
- **State isolation:** `HOME=<state>/<id>/home` so `~/.ducktape` (workspace
  registry) and `~/.local/share/com.ducktape.app` (app-data, daemon storage) are
  per-instance. `CARGO_HOME`, `RUSTUP_HOME`, `XDG_CACHE_HOME` and `PATH` are
  pinned to the real ones so builds stay cache-warm. Node ports auto-allocate via
  the app's own `bind(:0)` (`allocate_ports`), so no daemon collisions.
- Reuses the proven launch env: `WEBKIT_DISABLE_DMABUF_RENDERER`,
  `WEBKIT_DISABLE_COMPOSITING_MODE`, `LIBGL_ALWAYS_SOFTWARE`, `GDK_BACKEND=x11`,
  `dbus-run-session`, the `no-before.json` config override (skip the slow
  `beforeDevCommand`), and the xdotool focus + fill-to-framebuffer step.
- Per-worktree logs under `<state>/<id>/{xvfb,vite,tauri,x11vnc}.log`; a failed
  build for one worktree does not affect the others.

**Token routing:** writes one token file per worktree into `<state>/tokens/`
(`<token>: 127.0.0.1:<vncPort>`); the single websockify uses
`--token-plugin TokenFile --token-source <state>/tokens`.

### 2. `fleet.json` — the manifest (served at `/fleet.json`)

```jsonc
{
  "generatedAt": "2026-07-03T…Z",
  "host": "100.76.154.57",         // tailscale IP, for building ws URLs
  "webPort": 6080,
  "base": "dev",
  "worktrees": [
    {
      "id": "feat-qa-multiwindow",         // slug, = VNC token
      "branch": "feat/qa-multiwindow",
      "path": ".claude/worktrees/feat+qa-multiwindow",
      "head": { "sha": "2617e0a", "subject": "…" },
      "parent": "dev", "ahead": 3, "behind": 1,   // vs base (for later graph view)
      "slot": 1, "display": ":100", "vncPort": 5901,
      "token": "feat-qa-multiwindow",
      "status": "up" | "down" | "building"
    }
  ]
}
```

`ahead`/`behind`/`parent` are captured now (cheap) so the later xyflow view has
its edges without a data-layer change.

### 3. `ops/fleet-console` — the dashboard (Vite + React + TS)

- Deps: `@xyflow/react` (installed but v1 uses grid), `@novnc/novnc` (live RFB
  client). Built to static `dist/`, served by websockify.
- **Data layer** (`useFleet.ts`): polls `/fleet.json` every ~5s; exposes the
  worktree list + status. This layer is layout-agnostic (grid or graph consume
  the same hook).
- **`<AppTile>`**: header (branch, short sha + subject, ahead/behind, status
  dot) + a live **view-only** `@novnc/novnc` RFB canvas connected to
  `ws(s)://<host>:<webPort>/websockify?token=<token>`, `scaleViewport` on,
  `viewOnly` on (so hovering the wall can't fat-finger N apps).
- **`<GridView>`**: responsive CSS grid of tiles. Empty/`down`/`connecting`/
  `error` states per tile with reconnect-with-backoff.
- **Interaction:** click a tile → drawer with a full-size **interactive** RFB
  (viewOnly off) + "open in new tab" + connection details.
- **Later (not v1):** `<GraphView>` using `@xyflow/react`, same `useFleet` data,
  nodes laid out by `parent` depth from `base`.

## Data & control flow

1. `fleet.sh up` scans `git worktree list --porcelain`, assigns slots, launches
   each instance, writes `fleet.json` + token files, starts websockify.
2. Browser loads the console from `:6080`, fetches `/fleet.json`.
3. Each tile opens a WebSocket to `:6080/websockify?token=<wt>`; websockify maps
   the token to `127.0.0.1:<vncPort>` and proxies RFB; the canvas renders live.
4. Agents (in each worktree, via the tauri-debug socket) drive their apps; the
   dashboard reflects it live. `fleet.json` polling adds/removes tiles as
   worktrees come and go.

## Error handling

- **fleet.sh:** idempotent; guards each stage on `pgrep`/port checks (like
  `remote-tauri.sh`); one worktree's failure is isolated and shown as `down`/
  `building` with a log path; `status` never launches anything.
- **Console:** missing `fleet.json` → friendly empty state; a `down` tile shows
  a placeholder, not a dead canvas; RFB disconnects reconnect with backoff;
  token-not-found (worktree torn down) surfaces as `error` on that tile only.

## Testing

- **fleet.sh:** `status` + a `--dry-run` for `up` that validates slot math and
  emits a `fleet.json` without launching; a 1-worktree smoke bring-up asserting
  the token WS returns an `RFB` banner (same probe already used for
  remote-tauri).
- **Console:** Vitest + React Testing Library render `<GridView>` from a fixture
  `fleet.json` (RFB mocked) asserting one tile per worktree, correct labels, and
  status states; a unit test for the ws-URL/token builder.

## File layout

```
ops/
  fleet.sh                     # fleet manager (bash, userspace, no root)
  README.md                    # how to run + connect
  fleet-console/
    package.json               # @xyflow/react, @novnc/novnc, vite, react, ts
    vite.config.ts
    index.html
    src/
      main.tsx
      useFleet.ts              # poll /fleet.json (layout-agnostic)
      wsUrl.ts                 # build token ws URL (+ unit test)
      components/
        GridView.tsx
        AppTile.tsx            # live RFB canvas + header
        Drawer.tsx            # click-to-interact full session
      __tests__/…
docs/superpowers/specs/2026-07-03-agent-qa-fleet-dashboard-design.md
```

`~/.local/opt/remote-tauri/` stays as-is (single-instance tool + staged x11vnc/
xdotool/noVNC/websockify binaries the fleet reuses).
