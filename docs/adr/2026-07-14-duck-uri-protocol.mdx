# ADR: duck:// URI Protocol v1 — one grammar, one module table

Date: 2026-07-14. Status: **Accepted** (implemented in the same PR). The
`duck://` scheme becomes the app's deep-link fabric: one grammar, one module
table, one place to add a module. Before this, four consumers spoke three
half-different grammars — the chat tokenizer hardcoded `page|files`, the agent
runtime mirrored that pair in Rust, duckfs minted ad-hoc evidence URIs, and
the browser resolved `<name>.duck` gateway hosts — and a `duck://forge/...`
PR link in chat rendered as dead text. This document is the normative
protocol; the TS module table implements it.

## Decision, in one table

| # | Rule |
|---|------|
| R1 | One grammar: `duck://<authority><path>[@<rev>][#<fragment>]`; a dotless single-label authority is a **module** (this protocol), a dotted authority is a **gateway host** (gateway plane, unchanged) |
| R2 | The module table lives in ONE place — `app/src/backend/duck_uri.rs` (`classify_duck_link`) — and every surface (the open plane, the forge reader's Markdown images) classifies through it |
| R3 | An invalid or unknown ref never errors in a body: it stays literal text, losslessly |
| R4 | A chip's face is canonical/store data, never the authored markdown label (labels can lie) |
| R5 | Opening a ref maps onto the app's EXISTING navigation vocabulary via one handler (`open_message_link`, `handlers/chat.ice`); the protocol adds no navigation machinery — a two-step target parks a one-shot focus the second step's load consumes |
| R6 | Agent injection is per-module opt-in; v1 injects `page` and `files` only — the Rust parser is untouched, preserving the fuzz-verified "Rust refs ⊆ TS refs, the agent never over-reads" invariant |

## 1. Grammar

```
duck-uri     = "duck://" authority path [ "@" rev ] [ "#" fragment ]
authority    = module | gateway-host
module       = [a-z][a-z0-9-]*          ; single label, NO dots
gateway-host = contains "."             ; must end ".duck"
```

The chat/comment **reference form** is standard markdown link/image syntax
over a module-plane URI: `[label](duck://…)` / `![label](duck://…)`. Bare
URIs stay literal. References ride the wire as PLAIN markdown text — the chat
parser marks only `https?://` links — so the renderer and the agent runtime
parse the same bytes.

## 2. Module table (v1)

| module | path | chip face | open (deep link) |
|---|---|---|---|
| `page` | `/<id>` (one segment) | live store title, else raw id | `openPage` + pages screen |
| `files` | `/shared/attachments/<dir>/<name>` | filename chip; `![…]` embeds images | chip: download/preview; address bar: files browser |
| `forge` | `/<repo>` or `/<repo>/<n>`; `#<seq>` anchors a Discussion message (`n`, `seq` 1-based decimals); `/<repo>/blob/<path>[@<rev>]` names a committed file (no dot-segments; `rev` = an exact 40-hex oid reachable from the integration head — a branch name moves and is not an address; default head) | `repo` / `repo#n`; a blob `![…]` embeds the picture | repo → `forge_open_repo`; item → the one-shot focus `forge_repo_loaded` hands to `forge_open_item`, and `#seq` lands as the Discussion note's highlight once the discussion loads; blob → the Code browser's `focus_file`, which moves its tree to the file's directory at `@rev` (or its current revision) and opens the file under it |
| `channel` | `/<id>` (ids may contain `:`); `#<seq>` anchors a message | live `#name`, else raw id; `forge:<repo>:<n>` faces as `repo#n` | `selectChannel` / `focusMessage`; hidden `forge:*` discussion ids reroute to their forge item |

Reserved names: `memory` (agent-side evidence URIs, Rust-only), every dotted
host (gateway plane). duckfs evidence URIs (`duck://files<path>@<snap>#L<n>`)
remain an agent-facing convention outside the chat grammar.

## 3. Security invariants (carried, not new)

- `files` refs stay confined to exactly `/shared/attachments/<dir>/<name>`
  (two segments, no dot-segments) — classify is the only guard against a
  crafted ref steering a client read at another duckfs path; TS and the
  untouched Rust injector enforce it byte-identically.
- Widening the chat grammar must not widen agent reads (R6).
- The open plane is client-side navigation only — it grants no read the data
  layer wouldn't already serve.
- Labels are spoof-stripped (`displayName`) and chips never render them as
  the face (R4): `[not the pr](duck://forge/x/1)` renders `x#1`.

## 4. Adding a module

One `DuckKind` variant + one classify arm in `app/src/backend/duck_uri.rs`
(with its table test), one `match` arm in `open_message_link`, one row in §2. Injection stays off unless a
product decision defines what content the module's ref should pull into an
agent run.

## 5. Out of scope (v1)

Composer typeahead for forge/channel refs; chipping gateway-plane links in
chat; agent injection for forge/channel; OS-level `duck://` URL-scheme
registration (outside-the-app deep links).
