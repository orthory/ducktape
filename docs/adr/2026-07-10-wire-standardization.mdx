# ADR: Wire Standardization

Date: 2026-07-10. Status: **Accepted**. Ducktape's non-consensus wire
consolidates around three standard attach points — the data-plane `Service`,
the commonware-p2p mesh channel, and the app-facing `/v1` HTTP/WS surface —
with one big-endian header rule across all of them. Every new wire use picks
one of the three attach points and follows its template; hand-rolled parallel
codecs and channels that duplicate an attach point are refactoring debt, not a
design option.

## Context

Three independent campaigns (per-use data planes, the video-call build, the
private-cutover overlay) each grew their own wire without a shared rule, and
left three kinds of debt behind: the huddle call-socket frame duplicated
across three definition sites, statesync's mesh envelope drifting
byte-order from its overlay sibling, and two mesh channels
(`CHANNEL_VOICE`/`CHANNEL_VIDEO`) still registered and black-holed for a
media transport that had already moved to the overlay. This wire-standardization
campaign (four PRs against `dev`) resolved each in turn and this document is
the resulting map: what the three substrates are, the one endianness rule
that binds them, how to add a new wire use without creating the next round of
debt, and the decision log the campaign was built from.

### The three wire substrates

| # | Substrate | Attach point | Framing |
|---|-----------|--------------|---------|
| A | WireGuard-overlay **data plane** (`crates/system/data-plane/`) | `Service` enum variant (u8) + fixed overlay ports + `FlowId::derive(domain)` + consensus-derived `AdmissionPolicy` | one shared codec: 12-byte datagram header / length-prefixed stream hello (`wire.rs`) |
| B | Commonware p2p **mesh** (`bin/node/src/main.rs`) | numbered u64 channel + `network.register(...)`; statics 3–6, consensus engine bank at 9+ | per-channel, hand-rolled |
| C | App↔node **`/v1` HTTP/WS** (`bin/noded/src/lib.rs`) | axum route; streaming = topic on the multiplexed `StreamHub` (`bin/noded/src/stream.rs`) | serde-JSON, except two binary outliers (call socket, forge smart-HTTP) |

Substrate A consumers all follow one template (statesync, voice, video,
duckdns web — `Service` = 1..4). Every wire problem this campaign removed was
concentrated at substrate *boundaries*: the huddle hub translating between C
and A with duplicated frame definitions, and statesync speaking two envelopes
across A and B with drifted byte order.

## Decision

### The endianness rule (D1)

> Every structural header field on every Ducktape wire is big-endian (network
> order). Bulk payload bytes (PCM samples, Opus, VP8, request bodies) are
> opaque — their internal byte order is the payload codec's business and is
> documented, not converted.

Concretely: PCM stays little-endian i16 (it only exists on the loopback WS
leg; JS `Int16Array` is platform-LE), Opus/VP8 are opaque. Every length
prefix, flag byte, timestamp, and frame-type tag on every wire — data-plane
datagram headers, mesh channel frames, the call socket, statesync's length
prefixes on both bindings — is big-endian. There is no per-substrate or
per-service exception to the header rule; only payload bytes opt out, and only
because they are already fixed by an external codec (WebCodecs VP8, Opus, a
platform-native PCM array).

### How to add a new wire use

Pick the attach point that matches what you're building — do not invent a
fourth. Each recipe below is deliberately narrow: if what you're building
doesn't fit any of the three, that is a signal to slow down, not a reason to
hand-roll a parallel channel.

**A new data-plane service** (a new kind of real-time or bulk byte stream
between overlay peers — think voice, video, statesync, or a future
`Service::RunProgress`):

1. Add a `Service` enum variant (`crates/system/data-plane/`) — this is the
   single compile-time namespace *and* the overlay port registry, so the new
   variant also claims its fixed listener/datagram port.
2. Derive a `FlowId` for the domain (`FlowId::derive(domain)`) — flows are the
   per-consumer isolation boundary within a service.
3. Build the consumer's `AdmissionPolicy` — the plane never decides who is
   served; the injected policy does.
4. Bring the plane up through the shared helper in the `data-plane` crate
   (the D5 extraction from PR #329) rather than copy-pasting the bind-retry +
   `DataPlane::new` + `stream_service` registration boilerplate again.

**A new app-visible stream** (the app needs a live feed of something — a run's
progress, a job's log tail, a new notification class): it is a **StreamHub
topic**, not a new WebSocket endpoint. `bin/noded/src/stream.rs` already
multiplexes topics over one socket; a bespoke `/v1/.../ws` route re-litigates
the head-of-line-blocking and reconnect logic StreamHub already solved. (The
one standing exception is the call socket — see below.)

**A new consensus-visible fact** (something a module needs to record on
chain): it is a **module op carrying a digest or ref, never inline bulk
bytes**. Consensus ops are replayed and gossiped; a module that inlines a
blob's bytes into its op payload pays that cost on every validator, forever.
Stage the bytes through the appropriate blob surface (duckfs, `/v1/files/blob`,
forge packs — deliberately still three separate surfaces, see this campaign's
non-goals) and record only the resulting digest/ref on chain.

### Two legitimate exceptions

Standardization has exactly two carve-outs, both structural, not
convenience-driven:

- **Bootstrap-ordering exception → the mesh leg stays, for statesync.** The
  overlay is not always up when a node needs to talk: the statesync plane is
  env-gated default-OFF (`DUCKTAPE_STATESYNC_PLANE=1`), a parked
  (pre-admission) joiner has no overlay admission yet (`OverlayBook` only
  admits members/standbys) and must poll the mesh to detect its own admission,
  the overlay interface bind is async with a retry window, and a failed NAT
  punch is terminal with no relay fallback. Any consumer whose bootstrap can
  precede overlay readiness needs a mesh-leg fallback with pinned parity to
  its overlay sibling — this is not a general license to keep a mesh copy of
  every wire "just in case." (A related harness gap is tracked as issue #331:
  `ops/callbed` cannot bring up the WG overlay under coordinated-cutover
  defaults, which is exactly the ordering class this exception exists to
  survive — fix the harness before assuming a new consumer needs this
  exception too.)
- **Browser-boundary exception → one gateway hub, one codec site.** The
  browser webview cannot speak the overlay or the mesh directly; huddle media
  crosses through a gateway hub (`bin/noded`) that terminates a browser-facing
  socket and re-emits onto the data plane. That translation is real and
  necessary — but the frame *codec* it translates must have exactly one
  definition site (D2: `chat::call_wire`), never one copy per side of the
  translation. The exception is "a hub may bridge two substrates"; it is never
  "each side of the bridge gets its own copy of the wire format."

## Decision log

- **D1** — all wire *header fields* big-endian; payloads opaque (quoted
  verbatim above).
- **D2** — huddle call-socket frame definitions (previously duplicated across
  `bin/noded/src/lib.rs`, inline `call_session` parsing, and
  `app/src/domain/call-session.ts`) moved to one definition site,
  `chat::call_wire`, next to the existing datagram codecs
  (`chat/src/voice/media.rs`, `chat/src/video/frame.rs`). The PCM
  (local leg) / Opus (mesh leg) split is kept — the hub must decode to mix
  regardless, and loopback bandwidth is free.
- **D3** — dead mesh channels `CHANNEL_VOICE = 7` / `CHANNEL_VIDEO = 8`
  (black-holed since media moved to the overlay) were deleted outright, with
  no renumbering of surviving channels: gaps are free, churn is not.
- **D4** — statesync keeps BOTH transport bindings; its two envelopes are not
  unified. The asymmetry is intrinsic — a multiplexed lossy mesh channel needs
  `id‖frame` plus a reaper, a per-request overlay stream needs neither — and
  the mesh leg is not deletable, for four verified reasons:
  1. the statesync plane is env-gated **default OFF**
     (`DUCKTAPE_STATESYNC_PLANE=1`, `statesync_plane::enabled()`), so the
     mesh is today's *primary* path, not a fallback;
  2. a parked (pre-admission) joiner polls the manifest via statesync to
     detect its own admission (the park loop in `bin/node/src/main.rs`), and
     the serving validator's `OverlayBook` admission (members+standbys only,
     in `bin/node/src/statesync_plane.rs`) refuses it on the plane;
  3. the overlay interface bind is async (3s retry), so a window in which
     only the mesh leg is live always exists;
  4. a failed NAT punch is terminal (no relay since PR #173), so some peer
     pairs never get a tunnel at all.

  What was done instead: a parity test pinning both bindings to identical
  behavior, plus fallback visibility, and D1's big-endian length prefix
  applied to both.
- **D5** — the copy-pasted plane bring-up boilerplate
  (`bin/node/src/statesync_plane.rs` vs the since-deleted duckdns announcer
  plane:
  bind-retry loop + `DataPlane::new` + `stream_service` registration) was
  extracted into a shared helper in the `data-plane` crate, so the next
  service starts from the helper instead of a third copy-paste.
- **D6** — `/v1/call/ws` stays a separate socket (binary media on the
  multiplexed StreamHub would head-of-line block against catch-up bursts); it
  just consumes the D2 shared codec. This is the browser-boundary exception
  above, made concrete.

## Compatibility waiver and flag days

**Backward compatibility was explicitly waived by user decision on
2026-07-10.** Ducktape's standard practice — rebuild or lockstep-roll a
running network after a wire-breaking change — applies to every flag day
below; old and new node binaries must not be mixed once any of them has
landed, or a mixed-version pair's connection dies the moment the broken wire
is exercised.

- **PR #329** (D5, the data-plane bring-up helper) — compat-neutral, no wire
  change, merges freely.
- **PR #332** (D2 + D1) — the call-socket codec moved to the single
  `chat::call_wire` definition site; `/v1/call/ws` headers flipped to
  big-endian. Flag day.
- **PR #333** (D4 + D1) — the statesync overlay leg's length prefix flipped to
  network order, with a parity suite pinning both bindings. Flag day.
- **This change** (D3) — mesh channels 7/8 (`CHANNEL_VOICE`/`CHANNEL_VIDEO`)
  deleted outright; no wire-compatibility black-hole retained. Flag day, and
  the last one in this campaign — the only PR of the four that can kill a
  mixed-version peer's connection outright (an old binary that still sends on
  channel 7/8 meets a new binary that no longer has the channel registered at
  all, which the mesh treats as a protocol violation).

## Consequences

- Every future wire use has exactly one place to look before writing new
  transport code: this document's three recipes. A hand-rolled channel or a
  second codec definition site is now a review finding, not a judgment call.
- The two exceptions are narrow and named, so they cannot silently grow: any
  new claim of "this needs its own mesh copy" or "this needs its own codec
  site" must match one of the two listed structural reasons, not merely cite
  precedent.
- The decision log is the durable record of *why* — D4 in particular exists so
  a future contributor does not "simplify" statesync back down to one envelope
  and reintroduce the park-phase admission circularity that made the mesh leg
  load-bearing.
- Mixed-binary huddles across the PR #332/#333/(this change) boundary are not
  supported; the team's standard rebuild-or-lockstep-roll practice is the
  only supported upgrade path across this campaign.
