# ADR: Desktop Node-Control Boundary

Date: 2026-07-10. Status: **Accepted; revised for Iced on 2026-07-15**.

The native Iced process must never execute blocking node or key operations on
its UI/event loop. Those operations are serialized through one bounded
`backend::node_control::NodeControl` actor.

## Context

The desktop app is a native UI over a separate `ducktape-node` process. It must
create and join workspaces, perform membership ceremonies, protect the local
user key, and start or adopt the selected workspace's node. Several of those
operations still use short-lived CLI verbs because the node owns their wire
formats, signature preimages, and governance rules.

Blocking process waits and registry mutations cannot run on the Iced event
loop. Unbounded background tasks would still race registry/key load-modify-save
sequences and retain an arbitrary number of secret-bearing requests.

The boundary also has these constraints:

- Workspace configuration, ceremonies, key formats, and signature preimages
  have one source of truth in `ducktape-node`.
- Passwords and recovery phrases cross the process boundary through bounded
  stdin, never argv or environment variables.
- A selected workspace node is detached from window visibility. Explicit app
  shutdown stops it through the workspace supervisor.
- CEF is an isolated Browser-pane child. Browsed content has no path to the
  native backend or node-control actor.

## Decision

All blocking node control goes through the backend actor:

```text
Iced message/task ─┐
enrollment task ───┼─> Backend -> bounded NodeControl queue -> node sidecar
workspace service ─┘                                  \-> managed node
```

`NodeControl` owns a bounded Tokio channel and one serialized blocking receive
loop. Its invariants are:

- One operation runs at a time, so registry and key mutations cannot race.
- The queue holds at most 32 jobs and rejects immediately when full or gone.
- A job older than 30 seconds expires before execution; a cancelled caller's
  unopened job is skipped.
- A panic becomes a content-free error and does not kill the actor.
- Enrollment, signing, workspace, and process lifecycle operations use the
  same lane.

Only `backend::node_control` resolves or executes the sidecar. Resolution uses
the packaged sibling or an explicit development override, canonicalizes it,
and on Unix rejects missing, non-regular, non-executable, replaceable, or
untrusted paths. It never searches `PATH`, falls back to an old binary, or
passes arguments through a shell.

Short-lived verbs have a 30-second deadline and are killed and reaped on
expiry. Stdout and stderr are drained concurrently, capped at 1 MiB each, and
rejected when truncated. Argument count and bytes, secret stdin bytes, NULs,
and line delimiters are bounded. Secret buffers use `zeroize` before release.
The backend refuses elevated/root execution.

The managed workspace process is started, adopted, checked, stopped, and
restarted by `backend::workspace_service` and its supervisor. The UI receives
typed Rust results through Iced tasks; there is no JavaScript IPC command
surface. The static React twin only dials a configured node and never manages
local processes or keys.

## Alternatives considered

- **Run commands directly from Iced updates.** Rejected: process, filesystem,
  and readiness waits would stall event handling.
- **Spawn one blocking task per action.** Rejected: it provides no admission
  bound or serialization for registry/key mutation.
- **Import node internals into the UI process.** Rejected: it duplicates
  security-sensitive rules and couples UI failures to consensus code.
- **Use the raw loopback RPC for every operation.** Rejected for now: it is a
  low-level node protocol, while the CLI still owns complete ceremonies.

## Future transport

The desired end state is a versioned, intent-shaped local administration API
with request IDs, deadlines, cancellation, bounded admission, and typed errors.
It should use authenticated Unix-domain sockets, Windows named pipes, or a
capability-gated loopback endpoint. Secret fields remain out of argv and logs.

`NodeControl` is the migration seam: operations can move from short-lived CLI
verbs to that transport without changing the Iced service API or moving crypto
rules into presentation code.

## Consequences

Serialization deliberately trades node-control concurrency for deterministic
mutation and a small audit surface. A wedged verb can delay later control work
only until its deadline; it cannot block window rendering or grow work without
bound. Unit tests cover serialization, panic recovery, backpressure, expiry,
process deadlines, path permissions, bounded output, secret delimiters, and
managed-node lifecycle. Real native-window and CEF smoke tests remain release
gates.
