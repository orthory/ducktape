# Iced desktop shell with an isolated CEF browser

**Status:** Accepted

Ducktape's desktop application is a native Rust application built with Iced.
The React console remains a static design and behavior reference, not a second
desktop runtime. Tauri, its command bridge, and its WebView are not part of the
shipped application.

## Boundaries

The shell owns native window IDs, navigation, workspace selection, process
lifecycle, notifications, and other application-wide capabilities. User-facing
views update capability-free state and emit typed effects through `view_api`
and `module_host`. Only trusted adapters may turn those effects into node,
backend, filesystem, process, clipboard, or browser work.

The composition is deliberately static. Concrete enums make the authority and
event source visible without committing the project to a plugin ABI. A view may
later move into its own package once it has a real independent release or test
boundary; file size alone is not a reason to introduce another layer.

Dependency tests reject backend, transport, browser, OS, filesystem, network,
and process imports from the view boundary. This is the contract future view
packages inherit.

Home and Chat are concrete, cohesive view modules behind the existing user
facade. Pages and Files keep their own domain boundaries. Huddle owns its UI,
session, and media runtime as one unit, while the shell retains the native
window ID, CEF visibility, and backend dispatch. Operator screens and their
trusted services use matching concrete domain modules behind stable facades;
the signed Gateway mutation and recovery transaction remains cohesive. The
shell's private presentation child owns only titlebar, rail, notification, and
window composition. These seams follow actual state and capability ownership;
the application does not split views merely to meet a file-size target.

## Native Terminal

The operator Terminal is an Iced view backed by a trusted Rust service. It is
not a browser tab and never creates a CEF surface. A single-user session owns
keyboard and IME input, selection, scrollback, and geometry. A shared session
is read-only at the PTY surface: attributed commands enter only through the
ordered command lane and its second topic. The trusted service owns the single
node WebSocket used to create, subscribe to, write to, resize, and close either
kind of Codex terminal session.

Terminal output carries a monotonic cursor. A reconnect resumes after the last
delivered cursor instead of replaying retained ANSI bytes into an already
populated emulator. A lagged stream is fatal because an evicted VT prefix
cannot be reconstructed safely; the UI asks the user to restart the session
rather than displaying a plausibly wrong terminal. Leaving Terminal, changing
workspace, or quitting serializes session shutdown before another session may
start.

## Browser exception

CEF remains embedded exclusively for the Browser surface. Publisher content is
never rendered by Iced and receives no shell or application IPC. Navigation is
limited to signed `.duck` authorities. Direct HTTP, HTTPS, file, loopback, and
local-network navigation are denied.

CEF resolves `duck://` requests through a native scheme handler. The handler
forwards bounded requests to the active node's dedicated browser-gateway
listener; the renderer never receives the node API address. Workspace changes
invalidate the old gateway generation, permissions, browser surfaces, history,
cookies, and in-flight responses before a new gateway is selected. Tabs own
separate CEF surfaces so switching tabs does not synthesize a reload.

CEF and its generated bindings are pinned as one versioned unit. macOS and
Windows packages ship the matching framework/runtime and helper processes;
Linux packages ship the runtime beside the executable.

## Rootless lifecycle

The desktop refuses root on Unix and administrator elevation on Windows before
CEF, tracing, filesystem access, node control, or window creation. Installation
and mutable state are current-user scoped. Desktop-owned directories and files
are hardened to `0700` and `0600` on Unix, symbolic-link state targets are
rejected, sensitive files use same-directory atomic replacement, and managed
node children start with `umask 077`.

Adoption and termination require an exact canonical executable and argument
match. The app does not kill a process based on a name or substring.

Loopback TCP is not a user boundary on a multi-login macOS machine. The
existing node control listener therefore does not yet provide cross-login UID
isolation. Closing that boundary requires a workspace capability consumed by
all desktop, CLI, MCP, filesystem, and Git clients; a desktop-only bearer would
be incomplete. Until that protocol migration lands, rootless means no elevated
process or shared installation state, not isolation from another logged-in user
who can reach the same loopback ports.

## macOS

The bundle targets macOS 14 because the native screen-capture dependency uses
the macOS 14 API. AppKit owns the application lifecycle and native traffic-light
controls while Iced draws the full-size titlebar content underneath. CEF helper
shutdown, close-to-menu-bar, Dock/Finder reopen, Cmd+Q, code signing, hardened
runtime entitlements, notarization, stapling, and Gatekeeper assessment are
release gates. The pinned Iced 0.14 stack does not currently expose an
AccessKit-equivalent macOS semantic tree; tooltips preserve sighted
discoverability but not VoiceOver parity. A production release therefore also
requires an accessibility backend or an explicit product decision accepting
that limitation. Linux CI cannot satisfy that gate.
