# ADR: Join Protocol v1 — invitation-gated admission

Date: 2026-07-13. Status: **Accepted** (design approved; implementation lands
as campaign PR4 on top of the targeted-invites cutover). Joining a Ducktape
network becomes ONE synchronous, invitation-gated handshake: a joiner that
does not pass the gate gets nothing — no tunnel, no lobby residence, no
chain state — and a joiner that passes leaves the handshake already holding
consensus-granted standing. This document is the normative protocol; every
implementation step cites the section it implements.

## Context

The pre-gate join was eventually-consistent: the joiner fire-and-retried an
advisory lobby announce, redemption was auto-submitted on its behalf,
replies were informational, and the joiner's authoritative admission signal
was polling chain state from a parking loop. Admission state was scattered
across five unreconciled signals (app log-marker classification, members'
in-memory join queues, the registry's join-time `member` flag, the joiner's
manifest polling, leftover on-disk invite files), which produced a standing
class of bugs: joiners waiting forever on spent invites (fixed piecemeal in
PR #538), surfaces disagreeing ("joined network shows admission unclaimed"),
and doomed joins acquiring tunnels and lobby residence before dying. The
campaign's targeted-invite cutover makes every deterministic reject
decidable by a single member at handshake time — the precondition this
protocol builds on.

## Decision, in one table

| # | Rule | Enforced at |
|---|------|-------------|
| R1 | Every admission decision rides ONE request/response gate; there is no advisory announce | §3 |
| R2 | Fail the gate ⇒ no tunnel, no residence, no retry-forever: rejects carry a terminal bit and terminal means the joiner process exits | §3.3, §4 |
| R3 | Pass the gate ⇒ the reply IS the admission: the member settles `Redeem` through consensus before answering | §3.2 |
| R4 | Zero chain state before standing: no statesync/manifest attempts pre-admission (client), no statesync/manifest service to standing-less keys (server, fail-closed) | §5 |
| R5 | One join-state machine, node-owned, one RPC; the app renders nothing else | §6 |
| R6 | In-place hard cutover: the gate replaces the lobby announce wire; no compat decode, no version negotiation | §7 |

## 1. Roles and artifacts

- **Invite token**: `{ issuer, nonce, target: Option, role,
  expires_unix_secs, sig }`, sig over `binding ‖ nonce ‖ kind[‖ target] ‖
  role ‖ expires` in the invite-grant namespace — the signature-covered
  kind byte says whether a target follows (targeted) or not (bearer), so
  neither form replays as the other. The blob envelope carries descriptor +
  reach + WG bootstrap + fronts, issuer-signed.
  *(2026-07-16, bearer-client-invites: `target` became optional. A bearer
  token is CLIENT-role-only and never enters this protocol — it redeems
  over a member's `/v1/submit` via `user-redeem-invite`, granting
  submit-only client standing. Everything below concerns node joins, which
  remain targeted-Resident-only.)*
- **Joiner**: the key equal to `token.target`. Proves possession via the
  join proof (`binding ‖ nonce ‖ joiner`).
- **Gating member**: any CURRENT VALIDATOR (v1: validators only — a gate
  needs to submit `Redeem` and observe its consensus fate; the relay lane
  already reports frame fates). The joiner's candidate list is the invite's
  inviter + fronts, filtered to validators as discovered.

## 2. Phase A — first contact (transport bring-up, gated)

The UDP intro / tunnel bring-up keeps its transport shape
(`IntroRequest`/`IntroAck`) but runs the FULL §3.1 validation checklist
before installing a tunnel peer. A refused intro answers
`IntroAck { installed: false, reason_code, detail }` and installs nothing:
a doomed join never obtains a tunnel (R2). The WG-key binding signature
(`INTRO_WG_NAMESPACE`) is unchanged.

## 3. Phase B — the admission gate

Wire: substrate B of the wire-standardization ADR — the existing lobby mesh
channel (`CHANNEL_LOBBY`), JSON, low-volume. The `LobbyMsg` announce enum is
REPLACED by:

```rust
enum GateMsg {
    // joiner → member. token fields verbatim + the announcing key + proof.
    Request { issuer, nonce, token_sig, joiner, proof, target, role, expires_unix_secs },
    // member → joiner. terminal ⇒ the joiner stops (exit) instead of failing over.
    Rejected { code: RejectCode, detail: String, terminal: bool },
    // member → joiner. the AUTHORITATIVE admission: Redeem is COMMITTED.
    Admitted { height: u64, cap: Option<Vec<u8>> }, // cap = private-coordination CoordCap, as today
}
```

### 3.1 Member validation checklist (normative order)

| V | Check | On failure: code (terminal?) |
|---|-------|------------------------------|
| V1 | decodes + well-formed | `BadEncoding` (T) |
| V2 | token sig verifies against this network's binding | `BadToken` (T) |
| V3 | `joiner == target` | `NotTarget` (T) |
| V4 | `now < expires` (member wall clock — the ONLY expiry authority besides joiner decode: `consensus_time` is block height on this chain, so no deterministic in-consensus expiry exists; single-use bounds the residual window of a colluding submitter) | `Expired` (T) |
| V5 | join proof verifies | `BadProof` (T) |
| V6 | nonce unspent in committed redemptions | `Spent` (T) |
| V7 | issuer in committed valset | `IssuerUnknown` (**non-terminal**: a lagging local view cannot distinguish removed from not-yet-seen — PR #538 review finding; the joiner fails over to another member) |
| V8 | role supported (`Resident` — a `Client` token grants submit-only standing and redeems via `user-redeem-invite`/`/v1/submit`, never over this gate) | `RoleUnsupported` (T) |
| V9 | joiner not already holding standing | short-circuit **success**: reply `Admitted { height: current }` (idempotent — a re-gated joiner is not an error) |

### 3.2 Settle-then-answer

V1–V9 pass ⇒ the member submits `GovMsg::Redeem` and AWAITS the frame's
consensus fate (the relay/submit lane already reports it), bounded by
`GATE_SETTLE_TIMEOUT = 30s`:

- committed ⇒ `Admitted { height }`
- deterministic consensus reject ⇒ `Rejected` mapping the module error
  (`Spent`, `NotTarget`, … — consensus is the authority for everything it
  can decide; V1–V8 are the cheap pre-filter. Expiry is the exception:
  consensus has no wall clock, so V4 at the gating member is final)
- timeout / submit failure ⇒ `Rejected { code: Busy, terminal: false }`

One in-flight gate per joiner key per member; a duplicate `Request` while
settling re-arms the same pending reply (no double-submit — the nonce set
makes racing members collapse to one grant regardless).

### 3.3 Joiner FSM

```
candidates = [inviter] ∪ fronts (validators)
for round in 1..=3:
  for c in candidates:
    send Request; wait ≤ GATE_ATTEMPT_TIMEOUT = 45s
    Admitted        → persist standing marker; → Phase C
    Rejected{T}     → EXIT fatal, naming code + detail  (R2)
    Rejected{!T}/timeout → next candidate
EXIT fatal "no member could settle the gate" (R2)
```

No un-bounded retry exists anywhere in the join path. The restart/restore
path (persisted standing) does not run the gate.

## 4. Reject codes

`BadEncoding | BadToken | NotTarget | Expired | BadProof | Spent |
IssuerUnknown | RoleUnsupported | Busy`. Terminal bits per §3.1. Codes are
wire-stable identifiers; `detail` is human prose and MAY change freely.

## 5. Phase C — statesync strictly after admission

- **Client**: pre-admission a joiner runs ONLY this protocol — no manifest
  polling, no sync client, no boundary fetches. Admission detection IS the
  `Admitted` reply; the park loop's poll-to-discover-own-admission is
  retired from the join path.
- **Server (the security boundary, fail-closed)**: members refuse
  statesync/manifest service to any key without committed standing
  (validator/resident). A valid targeted invite alone leaks zero chain
  state (R4). The lobby channel carries gate traffic only.
- **Exemption**: a node restarting with persisted standing is the restore
  path, not a join — it syncs as today (guards against whole-net
  bootstrap deadlock).

### 5.1 Enforcement — real-key standing proof (not a transport-key gate)

A transport-key gate is IMPOSSIBLE: a parked joiner and an admitted-but-
not-yet-rebooted resident present the SAME derived **lobby** key on the
statesync channel (`boot/mesh.rs` picks the lobby key whenever `joiner`, and
`joiner` stays true until the promotion reboot). The serve loop cannot tell
them apart by transport identity — documented at `validator/wiring.rs`.

The node still HOLDS its real signer while transporting under the lobby key
(exactly as `GateMsg::Request` proves the real joiner key over the lobby
channel). So enforcement keys off a **request-level proof of possession of
the real key**, checked against committed standing:

1. Each `SyncRequest` carries `{ requester: real_pubkey, proof: sig }` — the
   requester signs a binding (genesis namespace ‖ request nonce) with its
   real signer. Additive to the tag-based `SyncRequest` codec.
2. The serving validator verifies the PoP, then checks
   `requester ∈ (read_valset_members ∪ read_valset_residents)` — a members∪
   residents snapshot refreshed at each epoch cutover (cheap in-loop read,
   no per-request round-trip). An admitted resident's real key is in
   `residents` the block after `Redeem` commits; a pre-admission joiner's is
   not, despite the shared transport key.
3. Unproven / non-member requests are refused. The restore path needs no
   exemption: a node with persisted standing dials under its **real** key and
   that key is already in the committed valset, so the gate admits it
   naturally. The standing read is against the server's OWN restored host
   state (a local read), so a simultaneous whole-net restart cannot deadlock.

**Cutover**: the proof FIELD is additive, but ENFORCING fail-closed rejects
old clients, so turning it on is a coordinated in-place cutover (no compat
path, standing mandate) — the whole set updates together, same as every
other flag day in this campaign.

## 6. Join state — one machine, one RPC

Node-owned, derived ONLY from gate progress + committed chain state:

```
Unjoined → GateInProgress(candidate, attempt)
         → Admitted(height) → Synced(boundary) → Promoted(epoch)
         → Rejected(code, detail)            [terminal]
```

Exposed via a single `join-state` RPC. The app's daemon.log phase
classification (`phase.rs classify`) is RETIRED; JoinProgress, pending-join
surfaces, and node-page banners render the RPC verbatim. The workspace
registry's cached `member` flag is dropped in favor of the RPC; the on-disk
invite token file is deleted at `Admitted` (a consumed credential must not
survive to confuse a later boot). The observed "joined network shows
admission unclaimed" symptom is the acceptance repro for this section.

## 7. Cutover

In-place, no backward compatibility (standing mandate): `GateMsg` replaces
the lobby announce wire, old joiners and members do not interop, invites
live ≤7 days, the valset updates together. No version negotiation, no
compat decode, no namespace bumps.
