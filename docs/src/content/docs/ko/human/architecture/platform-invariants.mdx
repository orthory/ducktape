Ducktape는 다섯 가지 invariant를 중심으로 설계되어 있다. 이 규칙들은 스타일
선호가 아니라, 독립 validator들이 같은 agreed operation order에서 같은
root-hash를 계산하게 만드는 조건이다.

## Isolation

product module은 `sdk::Module`을 구현하는 crate다. 일반적으로 `sdk`와
대화해야 하는 모듈의 crate-root wire type에만 의존한다. 호스트가
보는 것은 module id, `execute` entry point, optional read projection,
commit/abort hook, 그리고 `root() -> StateRoot`이다.

모듈은 다른 모듈 구현을 직접 호출하지 않는다. read는 `Ctx::query` 또는
`Ctx::module_root`를 사용한다. write는 `Msg` intent로 emit되고 호스트가
local follow-up으로 다시 dispatch한다.

## Determinism

consensus delivery부터 `root()`까지의 모든 단계는 agreed op order의 결정적
함수여야 한다. state machine은 agreed height/time, sorted map, explicit byte
payload를 사용한다. wall clock, random choice, network IO, LLM call, external
fetch는 module execution 안에서 실행되지 않는다.

## Host-Lent Atomicity

모듈은 `execute` 동안 write를 stage한다. block boundary는 호스트가 소유한다.
clean drain이면 touched module마다 `commit_block`을 호출하고, error 또는
dispatch budget breach가 있으면 `abort_block`을 호출한다. 실패한 block은
module root를 바꾸지 않는다.

## Root-Hash Commits to Everything

중요한 durable state는 module root 아래에 있어야 한다. global root는
`(module_id, module_root)` pair를 정렬해 hash한 값이다. QMDB root, forge의
git-head root, canonical in-memory snapshot 모두 같은 방식으로 합성된다.

## Single-Store Step

결정적 step은 하나의 store에 write한다. cross-store work는 follow-up message
또는 saga/worker pattern으로 순서화한다. 이 규칙은 two-phase commit을 피하면서
호스트가 block-level atomicity를 제공하게 한다.
