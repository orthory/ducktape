consensus는 order-dependent module root를 안전하게 만드는 단일 agreed order를
제공한다. node layer는 finalized op에 agreed view-derived environment data를
찍고 host에 전달한다.

## Ordered Delivery

QMDB root는 operation-log commitment다. 같은 최종 key-value set도 write order가
다르면 다른 root를 가질 수 있다. 따라서 Ducktape는 eventual arrival order에
의존할 수 없다. validator는 같은 agreed sequence를 apply해야 한다.

`OrderedNode`는 host와 `Orderer` 사이의 seam이다. finalized op는 view order로
drain되고, host는 finalized view에서 나온 explicit `BlockContext`를 받는다.

## Commonware Simplex

consensus crate에는 commonware Simplex-backed orderer가 있다. 현재 책임은 다음과
같다.

- content-addressed ingest, receipt 시 payload byte 재해시;
- relay path를 통한 eager payload gossip;
- inbox를 통한 view-keyed finalized release;
- late joiner와 missing payload를 위한 resolver fetch;
- V1 ed25519 및 future rekey/respawn behavior의 scheme documentation.

malformed finalized op는 consensus 관점에서 deterministic no-op이다. host가
reject하거나 rollback하지만 honest node를 멈추지 않는다.

## Node Paths

repo에는 두 node style이 있다.

- `Node<T>`는 local convergence를 위한 초기 loopback transport seam이다.
- `OrderedNode<O>`는 consensus-finalized op를 apply하는 ordered lane이다.

`bin/node` 아래의 real-socket binary는 commonware networking 위에서
`OrderedNode<SimplexOrderer>`를 구동한다. two-process demo는 두 OS process가 TCP
및 Simplex를 통해 하나의 app-hash로 수렴할 수 있음을 증명한다.
