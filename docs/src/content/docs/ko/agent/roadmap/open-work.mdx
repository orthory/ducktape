이 page는 agent가 실수로 완료된 것처럼 말하면 안 되는 implementation gap을 기록한다.

## WireGuard Tunnel Runtime

`crates/system/wireguard`(crate root가 validation, `wireguard::effect`가 apply
layer; 이전의 `wireguard-upgrade` + `wireguard-effect` crate가 merge된 것)는 더
이상 protocol leaf가 아니다. node의 reachability plane이 검증된
`TunnelInstallPlan`을 설정된 `WireGuardEffect`로 apply하고, parallel
`valset::mesh` contract는 unify 대신 삭제됐다. 실제 WireGuard interface를 Linux
netns에서 올리는 privileged e2e는 아직 deliberately descoped다.

## Demotion And Promotion Edges

epoch cutover에서 validator set에서 빠진 validator는 아직 sync/resident로 남지 않고
halt한다. joiner promotion 자체는 shipped 상태다. parked joiner는 admission boundary를
sync하고 promotion checkpoint를 쓰고 reboot한 뒤 vote할 수 있다. 이것을 missing으로
기록하면 안 된다.

남은 promotion-adjacent operator work는 stale local-state story다. pre-recovery 또는
damaged recovery directory는 migrate되지 않고 loud failure로 끝나며, demoted node도
아직 자동으로 resident role로 degrade하지 않는다.

## Replay Nonces

ordered frame은 `(origin, seq)`를 carry하지만 replicated state는 per-origin nonce
monotonicity를 enforce하지 않는다. byte-identical frame의 cross-epoch replay는 현재
per-engine finalization dedup에만 걸린다. durable replacement는 committed nonce
state다.

## Restart-Recovery Compatibility

restart recovery는 live다. checkpoint, op-journal replay, cutover record, floor
certificate로 current node를 recover한다. 남은 edge는 older/pre-recovery storage
directory다. local state가 recovery checkpoint 없이 존재하면 boot는 in-place migrate가
아니라 wipe/re-sync 안내와 함께 loud failure로 끝난다.

## Agent Product Path

live node는 이제 module set에 `agent`, `runs`, `jobs`, `dispatch`, `saga`,
`capability`, `tagging`을 포함한다. local capability provider를 discover하고,
truthful tag set을 announce하며, 자기 key에 assign된 lease만 dispatch worker로
실행한다. 남은 product work는 기본 agent execution loop가 아니라 더 풍부한 operator
UX와 package-level behavior다: packaged agent와 harness, 더 넓은 action vocabulary,
task obligation, debug surface가 아닌 native하게 느껴지는 durable agent workflow.

## duckfs Product Edges

duckfs Phase 1–5의 core stack은 구현되어 있다: 다시 만든 `files` module(staging, atomic
per-path-CAS commit, snapshot, pin, watch, snapshot-addressed read),
full possession까지 가는 resolver-backed state sync, restart durability, noded
HTTP surface, checkout/commit engine(`crates/duckfs/client`, `.duckfs/` index),
CLI, FUSE mount. 이것들을 missing으로 기록하면 안 된다. 남은 duckfs work는
duckfs verb 위로 다시 만드는 app FilesView product integration이다.
`memory` module은 삭제되었다 — duckfs가 흡수했다(generation은 snapshot이 되고,
`duck://memory/...`는 `duck://files/...`가 되었다). automations memory-watch
trigger도 함께 제거되었다. filesystem-change automation은 migration이 아니라
새 duckfs-watch trigger라는 fresh feature로 돌아온다.

## Module Integration Wave

다음 module wave는 이미 존재하는 module 사이의 integration work다. automations가
inbox `Deliver`를 emit하고, automations trigger source가 duckfs(files) watch에서
오고, agent가 jobs를 claim하고, package harness가 agent와 action route를 소유하고,
tasks가 deadline state, cure/escalation lineage, atomic cross-module creation을
갖춘 obligation pattern이 되어야 한다.
