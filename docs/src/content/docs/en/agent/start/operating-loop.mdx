title: "Operating Loop"
---

Agents should work from repo evidence and keep unrelated worktree state out of
the change.

Related: [Verification Matrix](/en/agent/reference/verification-matrix) lists
the gates, [Repository Map](/en/agent/reference/repository-map) locates source
surfaces, [Quick Start](/en/human/start/quick-start) is the reader-mode entry,
and [State Sync Contract](/en/agent/architecture/state-sync-contract) covers
sync claims.

## Before Editing

- Check the current path, branch, and worktree list.
- Continue an existing task worktree when it already matches the branch.
- Fetch `origin` before publishing or rebasing claims against `dev`.
- Read the module or docs surface you are about to edit instead of relying on
  summaries.

## Docs Commands

The docs package uses Bun.

```sh
cd docs
bun install
bun run docs:check
```

For local viewing:

```sh
cd docs
bun run dev
```

## Rust Commands

Run these when the touched surface includes platform code or when docs claims
depend on current Rust behavior.

```sh
cargo test --workspace
cargo run -p demo
cargo test -p demo --test network_joiner_full
```

## Publishing

For docs-only PR updates, include the Bun docs check, a draft-text scan, and
`git diff --check origin/dev...HEAD` in the PR evidence.
