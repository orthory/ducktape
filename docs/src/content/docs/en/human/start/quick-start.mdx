The repository is a Rust workspace. The docs are a separate Nimbus project under
`docs/`, so Rust verification and docs verification stay decoupled.

## First Run

Launching the desktop app for the first time opens two gates in order: an
identity, then a workspace.

**Create your identity.** Set a password — it encrypts this device's
identity key at rest and never contributes to key derivation — and the app
generates a 24-word recovery phrase, shown exactly once. Write the words
down in order, then confirm three of them (picked at random) before the app
lets you continue; skipping the confirmation isn't offered.

**Restore an identity instead.** On a new device, or after losing the
identity file, paste the 24-word phrase and set a new password for this
device rather than creating a fresh identity.

**What the phrase recovers.** The mnemonic is an exact encoding of your
identity's key material, so restoring from it reproduces the same identity
byte-for-byte and brings its on-chain display name back automatically once a
workspace connects (the `identity` module's user record — see [Product
Modules](/en/human/modules/product-modules)). It does **not** recover this
device's node key (`<workspace>/identity.key`). For a node that only follows
the network — a resident replica — that key is disposable: a lost device
rejoins from a fresh invite with a fresh one. For a node that holds a
**validator seat** it is not: below four validators every seat must be live
to finalize, so losing a seat key halts the chain until the seat is restored
or voted out. Back a validator's `identity.key` up off the host before it
is promoted — see the
[backup and keys](https://github.com/orthory/ducktape/blob/dev/docs/deploy/backup-and-keys.md)
runbook.

**Forgot your password?** There is no password reset — restore from the
24-word phrase and set a new password. The phrase is the only backup that
matters; losing both it and the identity file loses the identity for good.

Once identity is set, create a new workspace or join one from an invite, the
same as before.

## Platform Checks

Run the workspace tests:

```sh
cargo test --workspace
```

Run the in-process super-app demo:

```sh
cargo run -p demo
```

Run the invite/join/admit real-socket node demo:

```sh
cd bin/node
./examples/demo-invite.sh
```

Run the joiner state-sync proof directly:

```sh
cargo test -p demo --test network_joiner_full
```

## Docs Checks

Install the docs dependencies and run the docs gate:

```sh
cd docs
bun install
bun run docs:check
```

Start Nimbus locally:

```sh
cd docs
bun run dev
```

The docs project is intentionally rooted at `docs/`. Routed page files live in
`docs/src/content/docs`; the landing page lives in `docs/src/pages`.
