Most readers should start with the Nimbus pages, not temporary planning files.
The files below are the maintained records that still carry decisions,
protocol boundaries, or operator procedures that are too detailed for the main
tour. Reviewed active records that have not been folded into these pages yet
live under `docs/superpowers`.

Related: [Repository Map](/en/human/reference/repository-map) locates source
surfaces, [Gotchas](/en/human/reference/gotchas) lists recurring traps,
[agent Design Records](/en/agent/reference/design-records) is the edit-oriented
twin, [Coordination](/en/human/network/coordination) covers rendezvous records,
and [Open Work](/en/agent/roadmap/open-work) tracks live gaps.

## Historical Material

Implementation plans are not maintained as product documentation after the code
ships. The durable parts move into Nimbus pages, ADRs, or the module comments and
tests that now prove the behavior.

The current reviewed prune set is intentionally narrow: the completed sentry
phase-1 implementation plan, three explicitly historical coordinator-relay-era
plans, and the solved fleet-isolation finding.
Durable facts should move into:

- [Product Modules](/en/human/modules/product-modules) for pages, comments,
  agents, jobs, and the module wave;
- [Implementation Status](/en/human/reference/implementation-status) for what is
  checked in and tested;
- [Node Upgrades](/en/human/network/node-upgrades) and
  [agent upgrade operations](/en/agent/network/node-upgrades) for the upgrade
  policy and runbook;
- the ADRs listed above for decisions that should outlive the implementation
  branch;
- `docs/superpowers/README.md` for the reviewed working-record retention policy.

## Housekeeping Rules

- Put maintained reader docs under `docs/src/content/docs` so Nimbus can build and index
  them.
- Keep ADRs when they capture a decision boundary, not a task checklist.
- Keep runbooks when an operator still executes them.
- Delete or fold implementation plans once the code, tests, and Nimbus summaries
  supersede them.
