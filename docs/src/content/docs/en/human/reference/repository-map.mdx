## Kernel

- `crates/kernel/sdk`: module contract, context, messages, events, effects,
  origins, deterministic environment, `StateRoot`, and the shared snapshot
  codec toolkit (`sdk::codec`).
- `crates/kernel/host`: registry, dispatch, follow-up drain, block
  commit/abort lifecycle, global root-hash composition, and the
  non-deterministic worker seam (`host::worker`).
- `crates/kernel/node`: loopback and ordered node seams between host and orderer.
- `crates/kernel/consensus`: commonware Simplex orderer, content store, relay,
  finalized inbox, resolver fetch, and scheme boundaries.
- `crates/kernel/statesync`: network state-sync wire protocol and p2p binding.
- `crates/kernel/recovery`: restart durability — op journal, checkpoints,
  boot-time replay.
- `crates/kernel/indexer`: derived, node-local read index over the finalized
  op stream; never part of the root-hash.

## System

- `crates/system/kv`: QMDB byte-key value module.
- `crates/system/valset`: ed25519 validator membership module.
- `crates/system/saga`: deterministic continuation state for async workflows.
- `crates/system/governance`: validator-set governance over valset.
- `crates/system/identity`: canonical accounts, member keys, display names, and
  node bindings.
- `crates/duckdns`: `<handle>.duck` → AccountId naming. A LIBRARY, not a
  module — the `gateway` module embeds it and owns the on-chain half.
- `crates/system/wireguard`: validator-set-backed WireGuard tunnel-upgrade
  protocol; `wireguard::effect` is the apply layer.
- `crates/system/nat-traversal`, `reachability`, `data-plane`, `overlay-net`:
  coordinator-mediated hole punch, the node-driven WireGuard mesh
  orchestrator, off-consensus byte transport, and the userspace overlay seam.
- `crates/system/lifecycle`, `capability`, `dispatch`, and `tagging`: the
  module code registry, executor capabilities, capability-routed dispatch, and
  engagement routing.
- `crates/kernel/blobstore`: node-local content-addressed blob store, never in
  any root. `crates/modules/system/gateway`: `.duck` gateway route state.
- `crates/services/compute`: the dispatcher's host-side worker half
  (`compute-service`), off-chain and outside the module tree.
- `crates/services/provider`: machine-local executor providers behind the
  capability seam (`provider-host`).
- `crates/services/sandbox`, `broker`: the node-private podman/egress muscle
  and the run-scoped credential loopback the provider run loop drives.
- `crates/duckfs/client`: OS-side checkout/status/commit engine for duckfs; it
  stays off the consensus path.
- wire surfaces: each module publishes its types-only payload and query shapes at its crate root (`src/interface.rs`).

## Apps

- `crates/apps/forge`: git-backed project state.
- `crates/apps/pages`: nested block pages and comments on QMDB.
- `crates/apps/chat`: storage-owning chat module on QMDB, with hook fan-out.
- `crates/apps/agent`: agent registry, channel watches, and run records.
- `crates/apps/runs`: agent run composition, dispatch, and response state.
- `crates/apps/tasks`: small canonical task state.
- `crates/apps/vaults`: replicated opaque secret ciphertext.
- `crates/apps/inbox`: per-member notification queues delivered as follow-ups.
- `crates/apps/automations`: operator rules over the chat hook seam.
- `crates/apps/files`: the duckfs module adapter; it owns the consensus
  filesystem surface and absorbed the old memory/workspace role as ordinary
  duckfs snapshots, paths, and `duck://files/...` evidence.
- `crates/apps/jobs`: consensus-native work board.
- app wire surfaces: the crate-root types are the legal cross-module payload surface.

## Examples and Binaries

- `crates/examples/directory`: state-based directory module, registered in
  `bin/node` as the production canary.
- `crates/examples/greeter`: demo module that emits follow-up writes.
- `crates/examples/evm`: experimental QMDB-backed EVM module, registered in
  the `noded`/`simnode` genesis.
- `bin/demo`: in-process walkthrough of the registered module set.
- `bin/node`: real-socket node and unified `ducktape` CLI, including the `fs`
  working-copy and `mcp` server families.
- `crates/noded`: the daemon library behind the app HTTP/WebSocket surface (the `/v1` router, actor lane, index/blob/stream lanes, in-process testkit); `bin/noded` is the `ducktape-noded` process that serves it.
- `bin/simnode`: deterministic scenario node — noded's `/v1` wire over a
  test-scripted block producer.
- `bin/coordinator`: public or private rendezvous/STUN helper.
