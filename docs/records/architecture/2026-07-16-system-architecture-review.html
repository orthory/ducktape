0The system at a glance

One BFT-replicated state machine hosting isolated modules; each sdk::Module exposes one 32-byte sdk::StateRoot, and host::global_root (crates/kernel/host/src/lib.rs:55) folds the sorted (ModuleId, StateRoot) pairs into the app-hash that consensus commits.

Ducktape.app spawns ducktape-node, not noded app/src-tauri/src/daemon.rs::resolve_node_bin picks the bundled ducktape-node. bin/noded and bin/simnode are dev twins. All three serve the byte-identical /v1 surface via noded::serve / noded::router (bin/noded/src/lib.rs:524,880).
Kernel crates spawn no tasks crates/kernel/host and crates/kernel/node are passive libraries. Every loop in §5 lives in a binary; only crates/kernel/consensus spawns engine tasks (SimplexOrderer).
One binary, three role arms bin/node/src/main.rs::run_node dispatches to boot::sync_only::run, replica::run (park → sync → promote), or validator::run_validator, decided by recovery checkpoint + genesis membership (bin/node/src/main.rs:465-537).
Two genesis sets bin/node/src/host_state.rs::ProductionModules = 26 modules; bin/noded/src/main.rs::MODULE_IDS = 16 (no membership tier — a single-writer daemon has nothing to govern).
Determinism contract Between consensus delivery and sdk::Module::root, no wall clock, rng, network, or LLM may run inside sdk::Module::execute. Non-determinism re-enters as ordered ops (§3).
bin/coordinator is untrusted nat_traversal::Coordinator holds an advert book + nat_traversal::InviteStore, no key material; blob integrity rides the envelope signature, never the server.

1Flow — invitation → join → resident → validator

Minting the invite IS the admission decision. A targeted single-use token redeems automatically through governance::Governance::handle_redeem and grants resident standing (mesh + statesync + submit relay, no quorum seat). A validator seat is a separate governance act. Join Protocol v1 (docs/adr/2026-07-13-join-protocol.mdx) is fully implemented: bin/node/src/lobby.rs::GateMsg, bin/node/src/validator/run/ingress.rs::on_lobby, bin/node/src/replica/park.rs.

On Admitted, replica/park.rs persists standing, stores the CoordCap via save_coord_cap, and deletes the on-disk invite token. A terminal Rejected exits the process — no retry-forever exists in the join path.

Fail-closed.

  • InviteRole::Client (submit-only ACL via crates/system/clients) is minted-but-gated-off until protocol v1 — intended sequencing?
  • Promotion-by-re-exec (reboot_self()): durable design, or a phase-2 artifact? In-process fold is the noted follow-up in bin/node/src/main.rs:465-480.

2Flow — transaction lifecycle

OrderedNode::submit_frame never applies. An op is enqueued, BFT-ordered as sha256(frame), and applied only when OrderedNode::drain_delivered receives it — identically on every validator (crates/kernel/node/src/lib.rs:49-80). bin/noded collapses the middle: every submit is immediately its own block (bin/noded/src/main.rs::submit_and_drain).

Submitbin/noded/src/lib.rs::submit / submit_frame → NodeCommand lane Two lanes coexist on purpose. The /v1/submit origin string is honored only by bin/noded/src/main.rs::run_node; the validator intake (bin/node/src/validator/run/ingress.rs::on_http) discards it. Authorship = the frame signature under FRAME_NS = "ducktape:op-frame:v2" (crates/kernel/node/src/lib.rs:95), never a session.
Orderconsensus::SimplexOrderer engine tasks ConsensusAutomaton::propose peeks the pending FIFO — a digest is removed exactly once, at finalization (SimplexReporter::report). ConsensusAutomaton::verify votes only for digests whose bytes sit in ContentStore — payload availability.
Executebin/node/src/validator/run/drain.rs (100ms DRAIN_TICK) OrderedNode::drain_delivered applies the whole batch as one block via Host::submit_block. Ctx::emit_msg follow-ups are the only cross-module write path; MAX_DISPATCHES = 1024 caps the drain.
Commithost::Host SubmitError::Rejected = deterministic no-op on every validator. SubmitError::Fatal = commit/abort hook failed, registry indeterminate → fail-stop. Reject-on-replay inside Host::submit_block (crates/kernel/host/src/lib.rs:1233-1266) is the built-in non-determinism detector.
Index + pushbinary block loop → indexer::IndexStore, noded::StreamHub IndexStore::apply_block failure poisons the store (reads keep serving, writes refuse) — never the block. StreamHub::publish_block wakes noded::stream::stream_session tasks, which re-scan the op-log after each client's cursor (bin/noded/src/stream.rs:919-1041) — reconnect replay and live tail are one code path.
Readtwo tiers Point/typed reads: POST /v1/query → Host::query → sdk::Module::query_with over committed state. Scans/views: /v1/index/{module}/* → IndexStore::scan / view on MVCC snapshots. Rule (docs/records/specs/indexable-spec.md): nothing a root() commits to is ever read back from the derived tier.
Review here
  • Is the /v1/submit (trusted string) vs /v1/submit/frame (signed) boundary crisp enough that a future contributor can't widen the trusted lane onto a networked surface?
  • host::global_root is a plain sorted sha256 — defers light-client membership proofs (comment at crates/kernel/host/src/lib.rs:50-54). Keep the deferral?
  • Fastblocks (docs/adr/2026-07-10-ducktape-fastblocks.mdx) is still Proposed — sdk::Module::submission_class does not exist in the shipped trait. Priority?

3Flow — the async engine (oracle-as-op)

Non-determinism never runs inside sdk::Module::execute. It leaves as an sdk::Event, runs off-loop, and re-enters as an ordinary signed op in a later block. host::worker::Worker never holds a module handle — the returned sdk::Msg is the only way back in, enforced by type (crates/kernel/host/src/worker.rs:93-95).

crates/system/saga deterministic continuation ledger: (saga_id, attempt) idempotency (P5), same-block SagaCallback on terminal transitions (P6), permissionless SagaMsg::Crank deadlines on consensus_time (P7).
dispatch / dispatch-oracle the twin split: dispatch::DispatchModule validates Recipe contracts in consensus; dispatch_oracle::DispatchPool runs the provider CLI and is opinion-free — no prompt authored, no output parsed, no credentials touched.
capability / capability-host CapabilityMsg::Announce replicates who-provides-what as consensus state. Executors are data: crates/system/capability-host/specs/codex.toml and specs/claude.toml. Credentials stay host-side behind a per-run loopback broker.
Never-pop-stack a validated result lands in a mailbox and is delivered by a System-origin DispatchMsg::DeliverPending injected by host::Host in a later block (crates/kernel/host/src/lib.rs:724) — results never re-enter the block that agreed on them.

The full agent beat (also bin/demo block 7): chat mention → runs::RunsModule composes the entire model input in consensus (prompt = committed hash resolved from the blob lane) → dispatch::DispatchModule stages SagaMsg::Trigger → bin/node/src/oracle_pool.rs / bin/noded/src/oracle_pool.rs runs the provider CLI in its sandbox → the result re-enters signed → dispatch::DispatchModule validates the contract → next-block delivery → inbox::Inbox / chat::Chat follow-ups fan out in that block.

4Flow — transport bring-up (what kicks in when)

Two orthogonal planes (crates/system/reachability/src/lib.rs:9-12): the commonware-p2p TCP control mesh is untouched by all WireGuard machinery, which drives only the data tunnel. Addresses are deterministic ULAs — wireguard::ula_v6_prefix (/48 = fd ‖ hash(chain_id)) and wireguard::ula_v6_member_addr (/128 = hash(chain_id ‖ identity), crates/system/wireguard/src/lib.rs:540-566) — so the mesh agrees with zero coordination.

Backend choice one trait — wireguard::effect::WireGuardEffect — two impls: wireguard::effect::DefguardWireGuardEffect (TUN, kernel-routed, needs root; servers) vs overlay_net::userspace::UserspaceWireGuardEffect (boringtun Tunn + smoltcp VirtualStack in-process; desktop default). Wire-compatible by construction — one crypto core.
Tunnel-peer layering the only "upgrade" ladder (reachability/src/orchestrator.rs:161-217): ReachabilityCommand::InstallInvitePeer (join window) → standby pre-warm records → the epoch's validated plans (signed, mesh-versioned, checked by wireguard::validate_upgrade_as). Weakest dissolves as stronger lands.
Per-epoch, not per-connection reachability::orchestrator::run turns each valset cutover into one mesh: EndpointRecord gossip → EndpointAdvertisement → MeshView::verify → per-pair handshake → one apply_tunnel_plans per epoch.
Per-use data planes data_plane::OverlaySockets binds the member /128 per data_plane::Service (Voice=2, Video=3, Gateway=6, ModuleCode=8, Term=9 — datagram vs stream classes never unified), throttled by one shared overlay_book::shared_bulk_pacer. Never the control mesh.
Review here
  • Punch-failure-is-terminal (orchestrator.rs:855-858): a symmetric-NAT pair with no dialable side simply fails. Still right as the user base broadens?
  • Invite / standby / validated = three peer lifetimes managed in one reachability::orchestrator::Driver — is the complexity paying rent?

5Who owns every loop

The kernel owns none — every loop lives in a binary. Two folklore corrections: DRAIN_TICK = 100ms (bin/node/src/constants.rs:92) is validator-only — the bin/noded node actor has no timer at all; and crates/apps/automations is not a scheduler — Automations is an in-consensus hook reactor with no loop.
