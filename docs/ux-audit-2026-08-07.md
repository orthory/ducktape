# ducktape-app UX audit — 2026-08-07

Produced by an 8-lens source audit (58 agents) with adversarial refutation:
each finding was handed to a skeptic told to refute it, defaulting to
rejection when unsure, with the session's already-fixed and known-open lists
in hand. 36 findings survived.

Lenses: empty states / dead ends; copy that makes a checkable claim;
overflow and clipping; destructive-action weight; error and disabled states;
read-after-write staleness; built-but-never-mounted; theme symmetry.

# SHIP NOW — fix is determined

**1. Dark mode paints four kinds of body text at ~1.1:1 (invisible)** — `app/src/ui/theme.ice:411`; sites `app/src/ui/components/forge.ice:1601,1614,1711`, `app/src/ui/screens/forge.ice:675`, `app/src/ui/components/pages.ice:186,235`
Sees: in dark theme every unchanged (context) line of every forge diff, every PR review comment body, every staged review comment, and every Pages comment body renders blank while the author/timestamp beside it renders fine.
Fix: `panel_tile` is a plate token (dark #2e2d28 ≈ dark `surface` #22211d); swap all six `@text-panel_tile` to an inverting ink — `accent_fg` is already used on `review.body` at `forge.ice:1669`, 10.1:1 dark. Delete `panel_tile_lit` (zero call sites).

**2. Invite screens promise a member-approval step that does not exist** — `app/src/ui/components/onboarding.ice:1214` and `:1445`
Sees: the inviter is told "a member still has to approve it" and the joiner's phase ladder says "waits until a member approves this device"; `bin/node/src/cli.rs:1620` states the opposite ("minting the invite WAS the approval"), so a bearer blob is presented as gated and gets forwarded.
Fix: delete both clauses. `:1445` should say the phase waits on the invite being redeemed through the join gate (`park.rs:830` wording). Do NOT plumb the node's per-phase `detail` — that ladder is a static pre-join preview with no node to poll.

**3. Post-mutation read-back adopts a stale index's fallback — 3 call sites** — `app/src/backend/live.rs:683` (open_dm), `live.rs:541` (create_channel), `app/src/backend/chat.rs:975` (delete_page)
Sees: `submit_frame` returns on acceptance, so the immediate reload misses the write and `load_*_data` silently substitutes `channels.first()`/`pages.first()` — first DM with a peer leaves the DM header on screen while the composer posts into an unrelated public room; a new channel drops you into another room and also marks that room read; a deleted page stays listed and can be re-selected and re-installed into the editor.
Fix: transplant the correction `create_page` already carries (`chat.rs:951-968`) — each caller knows its id is good. `open_dm`/`create_channel`: when `data.active_channel != channel_id`, stamp id/name/empty messages/seeded members/policy flags. `delete_page`: drop `page_id` **and its descendants** (RemoveBlock deletes the subtree) then re-resolve `active_page`.

**4. Chat tells you to post into a composer it has disabled** — `app/src/ui/screens/chat.ice:467-471`
Sees: on a workspace with zero channels (first run lands here, `state.ice:104`) and in any empty archived / members-only channel, "Nobody has posted here. Send the first message below." sits above a greyed-out composer — in the members-only case directly above the gate note that says posting is refused.
Fix: gate the plate on the composer's own disabled expression (`empty(active_channel) || !empty(post_gate(...))`), and add the no-channel arm pointing at the sidebar's New channel button — same shape as `screens/pages.ice:420`.

**5. Zero-hit search renders nothing on three surfaces** — `app/src/ui/screens/chat.ice:985`, `app/src/ui/screens/pages.ice:457`, `app/src/ui/screens/overlays.ice:312`
Sees: a search that matches nothing lands in a terminal state identical to one that never ran — no "no matches", and in chat/pages no clear-× either, so the query sticks with no way to tell which happened.
Fix: add the zero-hit arm the Explorer already ships at `screens/storage.ice:641-642` (`if empty(hits) && !searching && !empty(trim(query))` → `EmptyPlate`). Palette has no × to ungate (Esc resets).

**6. A failed members load silently demotes you to "guest"** — `app/src/backend/roster.rs:125`, `app/src/ui/handlers/roster.ice:89`

Fix: return `""` instead of `"guest"` from `member_tier` on an unmatched roster — the "STANDING UNKNOWN" arm is already written and unreachable at `components/node.ice:305,341`. Flip `app/src/backend/tests.rs:744` and add an `if empty(...)` sibling for the badge at `settings.ice:246`. (Governance's note is a separate decision, item D.)

**7. Thread reply composer is live in a channel you cannot post to** — `app/src/ui/screens/chat.ice:1637,1660`, `app/src/ui/handlers/chat.ice:736`
Sees: the timeline composer is greyed with a gate note, but opening any thread gives a live Send — the reply is optimistically appended, rejected by the module, and rolled back with a raw `transaction was rejected (400 …)` banner. Same omission fires a Send while disconnected.
Fix: add `!connected` and `!empty(post_gate(active_channel_archived, active_channel_members_only, channel_members, user_key))` to `:1637`, `:1660` **and** `handlers/chat.ice:736` (the view `disabled=` alone doesn't stop the Enter path). Whether the 330px rail also shows the gate copy is a design call.

**8. "Load older messages" merges one channel's history into another** — `app/src/ui/handlers/chat.ice:611`

**9. Forge tracker shows the previous repo's issues/PRs and asserts "No issues" before the repo answers** — `app/src/ui/components/forge.ice:1747`, `app/src/ui/handlers/forge.ice:22`

**10. Backing out mid-load reopens what you just left** — `app/src/ui/handlers/forge.ice:231` and `:247`

# NEEDS A DECISION FIRST

**A. Three failure arms turn a failed load into "the network holds none"** — `app/src/ui/handlers/forge.ice:15`, `app/src/ui/handlers/roster.ice:43,52` (and `handlers/overlays.ice:45`, no flag at all)
Sees: a failed forge/agents/governance load prints "No repos yet…", "No agents registered…", "No proposals waiting — every decision on this network is finalized." as fact, with no error anywhere.
Question: these arms setting `answered` is the *documented* contract (`state.ice:110-112`), and these loaders re-run every live tick — so neither "don't set answered" (screen goes fully blank) nor "set `error =`" (global banner repaints every tick, Dismiss useless) is right. Decide: does each plate get its own failed state that says "could not load", and does a background-refresh failure deserve the global banner at all?

**B. Settings DANGER ZONE "Forget network" is enabled on remotes and always fails there** — `app/src/ui/screens/settings.ice:481`
Sees: connected to a saved remote, the loudest button in the app is live and returns the raw string "this endpoint is not one of this device's registered workspaces"; the picker's per-row Forget is where remotes are actually dropped, and nothing says so.
Question: gate the button on the connection being a registered local workspace, or route remotes to `forget_network(id, "remote")` (`onboarding.ice:819`)? The second changes what the button *does* on remotes.

**C. Provisioning step 2 says "Admin keypair" — the one role name this product refuses** — `app/src/backend/shell.rs:477`
Sees: the only user-facing "admin" string in the app, on the post-join provisioning ladder, teaching a vocabulary three separate doctrine comments say is not adopted (validator/resident/guest).
Question: "Founding validator key" would be a new lie — `workspace_identity` reads the *inviter's* genesis valset from the pinned descriptor, not this device's key. Decide what step 2 attests: this device's own identity, or the network descriptor it just pinned.

**D. `success_tick` and `agent_live` are frozen across both palettes but drawn as text** — `app/src/ui/theme.ice:222/369`, `:255/396`
Sees: `✓ finalized · h N` and `✓ synced` sit at 2.46:1 in the default *light* theme at 9px (the app's proof mark, hardest thing on screen to read); `INFO` sits at 2.36:1 in dark, losing its level column while WARN and ERROR keep theirs.
Question: both need a per-palette reading, which means choosing values — a palette call, not a mechanical one. Related, `components/node.ice:596` calls the log console "the one dark plate in the console", but `bg=primary` makes it the *lightest* surface in the app in dark mode; decide whether that plate inverts or stays a terminal (`panel_tile` exists for the latter) before fixing its inks (`node.ice:633,659,988` — timestamp gutter 2.10:1 dark; `ink_soft` is a one-token swap if the plate keeps inverting).

**E. Governance asserts "this node does not hold validator standing" from a bool that can't say "unknown"** — `app/src/ui/screens/governance.ice:33-37`
Rider on item 6: `members_is_admin` returns false on an empty roster, so a members-load failure produces a positive claim about your authority. Question: should the note suppress until the roster answers, or reword? (`components/forge.ice:1237` sets the rule that a GateNote belongs over a refusal the product actually performs.)
